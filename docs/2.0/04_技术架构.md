# 技术架构

应用由经营专用组合根启动，产品中不再加载旧通用玩法图或旧系统模块。

| 位置 | 职责 |
| --- | --- |
| `js/main.js` | 启动层、超时、恢复入口、首屏完成后的资源预加载调度、页面退出与热更新释放 |
| `js/core/GameApplication.js` | 当前会话、按公司等级开放页面与导航、操作提示、计时和资源释放 |
| `js/core/MerchantGameRuntime.js` | 真实时间推进、后台补算、自动存档与经营命令 |
| `js/data/merchant.js` | 三港供需、三货物、六船型、三科技、六级公司、距离、探索与经营参数 |
| `js/systems/merchant/MerchantSystem.js` | 校验、派遣、自动解除与返港释放、探索信号/航次/解锁、公司升级、采购、预览与结算 |
| `js/systems/merchant/MerchantExploration.js` | 持久随机信号、探索预览与独占派船、勘察返程、完成开港和事件校验 |
| `js/systems/merchant/MerchantOnboarding.js` | 五步软引导状态、真实出航与返港进度、完成/跳过及旧档兼容 |
| `js/systems/save/SaveSystem.js` | v26 资料投影、探索与软引导状态校验、原始备份、迁移、四槽导入导出 |
| `js/ui/MerchantUI.js` | 经营、船坞、市场和账本，同一派遣入口 |
| `js/ui/MerchantOnboardingPresenter.js` | 简短开场、可跳过软提示、发展方向与玩家结束入口 |
| `js/ui/MerchantToolsUI.js` | 当前设置、公司名称、手动存档工具 |
| `js/ui/MerchantExplorationPanel.js` | 星图未知信号、源港/空闲船选择、预览与派船反馈、探索进度、完成详情及键盘焦点 |
| `js/ui/MerchantStarmapProjection.js` | 实际经营及探索航次到只读场景投影 |
| `js/ui/StarmapRenderer.js` | 模块预加载与缓存、3D 场景初始化、加载/错误状态、首帧计时与绘制生命周期 |
| `js/ui/RendererThreeStarmap.js` | 已开放港口、探索信号、真实船位、固定镜头、实际首帧绘制与 GPU 释放 |
| `css/merchant-*.css` | 当前壳布局、组件与统一材质 |

`SurfaceManager` 与 `BlockingSurfaceDismissRegistry` 只提供通用阻塞弹窗、焦点和 Escape 生命周期。`SettingsCore` 与 `AudioManager` 管理当前画面/音效，不依赖已退出的玩法。场景灯光、材质、地表生成、建筑与舰体建模是当前美术生产的共享库。

软引导独立保存 `merchant.onboarding`，界面只展示与提交开始、跳过或结束；经营结果驱动实际出航和首笔返港步骤，不以创建失败任务伪造完成。引导不接管经营时钟、发奖励或锁导航，后台与自动解除仍由经营系统推进，不恢复旧引导模块。

科技参数集中在 `js/data/merchant.js`：三项费用为 3,000 / 9,000 / 27,000 CR，公司资格为三级 / 四级 / 五级，联运仍依赖前两科技。每个科技只通过对应的 `unlockShipId` 开放一种船型；研发与购买分别校验和扣款，现有研发状态不因改价重算。

探索参数集中在 `MERCHANT_EXPLORATION_RULES`：二级资格、唯一目标星云工厂、30–90 秒信号延迟、30 秒勘察及 360 CR 出发费用。事件随机状态与下次信号时点进入账本，命令复核目标、已开放源港、空闲船及首航货本保护；船只以事件身份排他占用。探索去返程沿用船速与商业距离，在同一事件轴补算，全部返港后才开放新商路。直接 `unlockPort` 命令拒绝执行，新功能不调用被删除的旧探索系统。

任务出航失败后，经营系统按完整预算与当前供需重算分配船的可盈利性，无盈利航次即停止整个任务。有效在途航次保留，预算与船只在全部返港后释放；只对同任务在途资金占用保留等待回款。待生效调整先安全应用再检查，停止时取消调整并释放仅新增预留船。可选 `stopReason` 写入任务及历史，旧存档缺省兼容；界面只显示状态与原因，不自行恢复任务或结算。

星图渲染统一入口使用 `idle / loading / ready / error` 四种状态。未准备好时展示通用加载层，实际 3D 首帧绘制后才进入 `ready`；模块导入或初始化完成不代表场景已显示。检测到加载失败、3D 不可用或上下文丢失后切换为错误状态，可重试或返回经营，不运行 2D 场景。星图 DOM 和构建物只保留 3D 场景入口；离屏标签与程序化纹理的 Canvas 绘制仍属于 3D 美术生成流程。

`StartupLoader.complete()` 成功后才调用 `schedulePreload()`，空闲任务只缓存动态模块 Promise，不进入启动等待链，不初始化 GPU、不修改经营数据。首次进入星图复用模块请求，再初始化并绘制真实首帧；计时分别记录模块等待、初始化、首帧与总耗时，以及资源是否已提前准备。预加载失败不报启动错误，释放会话时即使未进入过星图也取消尚未执行的空闲任务。

主星地表跳过最终被覆盖的中间计算；星云按列复用中心曲线，以 `Float64` 缓存噪声格点哈希，保留原双精度计算结果。此类优化以完整贴图 SHA-256 一致为准，不改变分辨率、像素比、抗锯齿或场景内容。具体本机测量与验收见[封版验收](05_2.0封版验收.md)，不推导其他硬件的固定性能收益。

当前布局由 `merchant-shell.css` 与 `merchant-workspace.css` 提供，`merchant-material.css` 在其后应用已确认的统一材质。删除含历史选择器的规则时，只移除退出的选择器；同一规则中仍被任务底板、详情、派遣抽屉、标题区或操作按钮使用的材质必须保留。浏览器回归同时比较实际容器和普通按钮的最终背景，避免只检查样式文件存在而漏掉视觉回退。

## 依赖检查

`npm run check` 执行 ESLint、当前经营接口的 TypeScript 契约检查和模块引用检查。检查拒绝缺失导入、静态循环、已退出系统目录以及 Three 渲染器回流启动图；资源提前准备仍通过动态导入，场景只在进入星图后初始化。旧功能的测试随对应模块退出，经营、持久化、镜头、资产、启动与通用焦点测试继续保留并更新。

## 原创资产

`npm run assets:scene` 通过项目锁定的 Three.js 和本机 Chrome 重建七项交付资产：四种舰体和主星、矿业港、工业港三种展示图。程序化源代码、展示 WebP、舰体 GLB、停泊阴影和来源哈希共同保留。`npm run check:scene-assets` 验证数量、来源哈希、文件哈希、裁切边界、面数及文件大小预算。

当前使用的空间站与碎石建模原语仍作为港口装饰和矿业实体使用；已退出的星球名册、旧探索规则和未使用资产文件不再留在交付目录。

## 本地运行与交付

`npm run simulate:growth` 在独立内存状态中以固定探索随机种子模拟主动补派（默认 42，可指定 `--seed=<整数>`）：每秒检查供需，仅在路线盈利且有足额货本时，用空闲原船创建新任务；二级后停用原船任务并等待返港，再调用真实探索命令，探索期间不派贸易，完成后才投入三港；升级与研发保留待补派货本。`npm run simulate:growth -- --with-research` 使用相同双港到三港三船配置，先研发当级科技再继续公司升级并记录研发时点，不采购进阶船。脚本不启动浏览器、不读写玩家存档；它额外模拟玩家反复派遣，游戏自身不恢复已结束任务，两条策略不是无人值守或离线收益测量，也不代表统一通关时长。

`npm ci` 后用 `npm run dev` 启动 4173 端口。`npm run build` 生成 `dist/`；静态包可通过 HTTP 服务器运行。浏览器回归配置仅包含当前 2.0 的用例，使用独立端口与存档上下文。

封版包在 `releases/`，发布清单逐文件记录当前源代码、文档、资产和构建物的 SHA-256。`npm run release:seal` 先执行代码检查、单元测试、资产验证和生产构建，再生成本地 ZIP 与清单；后续改动必须重新验收并封存。`npm run check:release` 核对版本、目录与内容哈希，避免未记录的改动。浏览器实际操作与跨浏览器检查仍需另外执行，不由封包脚本代替。清理前备份位于项目之外，不混入产品。

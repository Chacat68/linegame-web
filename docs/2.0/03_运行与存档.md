# 运行与存档

## 时间与账本

`MerchantSystem` 是资金、供需、任务、探索、船位和航次结算的唯一写入者。前后台经营使用同一套真实时间事件，关闭游戏后再次打开按已保存的时间补算。每个完整返港轮次只结算一次；去程抵达销售时尚不把整趟净利润发到自由现金。

运行时约每 500 毫秒更新一次；每 15 秒自动保存，成功操作、页面可见性改变与退出页面时立即保存。停止会话只释放监听器，不再次写回旧状态。读取其他槽位或重开先停止旧运行时，再建立新会话。

离线累计没有固定八小时上限，也不额外叠加一套离线奖励。每次推进最多处理 5,000 个事件以限制单次计算量；超过时保留未处理的时间，后续继续补算，不丢弃收益。补算维持已安排的规模，不自动购船、发起探索、研发或将利润复投。长期时长与收益节奏留待后续内容验证。

前台、后台和离线补算都执行同一自动解除规则：无货、需求耗尽或完整货本无法支持任何分配船盈利时，停止新航次；有效在途航次完整返港并结算一次，最后退回预算、释放船只。没有在途航次的任务立即结束。只有同任务在途货本暂时占用且完整预算与当前供需仍能盈利时继续等回款；已结束任务不因市场补货自动重新派遣，因此无离线上限不等于持续获得收益。

探索使用同一真实时间推进机制。公司二级后的随机状态、下一次信号时点和当前事件持久保存，不因刷新重抽；不自动派船。已开始的探索离线完成去程、30 秒勘察和返程，最后一次开放目标港口并释放探索船，没有额外 CR 或船只奖励。经营与探索排他占用同一艘船，不能重复分配。

## 当前存档

游戏版本 **2.0.0**，存档结构 **v26**。四个槽位：0 自动、1–3 手动。数据只包含公司名、自由现金、当前/查看星系和经营账本。元数据包含版本、槽位、保存时间、公司、现金、船数和任务数。

经营账本包含公司等级、港口开放状态、已研发航运科技、探索随机状态/信号时点/当前事件、软引导状态 `onboarding`、供需、船只、在途采购/收入/费用、任务预算、待执行调整、返港停止标志、可选停止原因 `stopReason`、轮次数与留存报告。停止原因随任务和已结束报告保留；零航次、零利润的合法解除记录也保留。可运行时对象、计时器、渲染器、视觉颜色和 DOM 状态不进入存档。

`merchant.onboarding` 只保存 `step`（0–5）与 `skipped`（布尔值），新局从 0 开始；当前 v26 存档的合法 0–5 步骤与跳过标志原样保留，跳过为真时步骤必须为 5。完成与跳过均持久保存，重新打开不重播已结束流程。真实出航、返港结算与查看报告决定进度，失败派遣不能推进出航步骤。软引导不写入额外资金、船只、市场奖励或加速时间。

## 转换与保护

v21/v22/v23/v24/v25 经营进度保留现有字段；缺少探索状态的早期存档补入探索状态，所有低于 v26 的旧档将软引导标为完成（step 5），不重新弹出开场或提示；v21 缺失的航运科技清单补为空数组，缺少公司等级时补为 Lv.1。保留商队、科技、开港、在途货物、周转货本、任务调整和账目，不把旧舰队或挂机资产接回经营循环。已经超过初始船位的船全部保留，仍可派遣与结算；只有新采购需先扩容到有空位。已开放港口和已研发科技不因新增等级门槛而收回，对应市场与船坞页面入口继续可用。

`stopReason` 缺失仍是合法旧存档，不重置资产、船只或任务。读取后按当前真实时间规则推进，旧的市场等待任务也可能正常自动解除，释放货本与运力；这不是存档清空。

旧存档已经开放的星云工厂继续保留，不重锁或再次收取探索费用。探索船及事件的占用和时间轴同时校验；损坏的事件不能变成重复派遣、瞬间解锁或重复扣款。

科技费用调整不回收已研发科技或已购船只，也不追扣历史研发支出；尚未完成的研发使用当前 3,000 / 9,000 / 27,000 CR 费用。公司三级、四级、五级的资格与联运前置保持不变，每项科技继续只解锁对应一种船型的可购资格。

没有经营账本的历史存档，只转换公司与自由现金，建立当前开局商队。旧舰船、装备和旧玩法资产不折算为新运力；原文件完整保留在本机备份中。

v25 到 v26 转换以 `startrader_save_before_v26_<槽位>` 另存原始 v25 字节，不覆盖已有历史备份。此前 v24 到 v25 转换以 `startrader_save_before_v25_<槽位>` 另存原始文件；此前 v23 到 v24 的 `startrader_save_before_v24_<槽位>` 备份继续保留，不占用最早的历史备份。首次历史转换在写入新存档前，以 `startrader_save_before_2_0_<槽位>` 保存原始文件。读取已有经营进度失败、存档损坏或来自未来版本时，不静默新建游戏，不覆盖原数据，启动恢复页允许重试和导出原始文件。只有用户明确选择重新开始才删除自动槽位。

存档校验同时覆盖历史任务和逐笔航次：拒绝空记录、重复任务 ID、无效货物或港口、损坏时间与金额，以及收入、采购、费用和净利不一致的记录。在途账目按实际货量、港口价格和完整往返费用核对；任务可用货本与在途采购/费用合计必须等于任务预算。新增身份序号不得回退到已有船、任务或历史记录使用过的序号。损坏报告或资金不守恒的数据不会进入界面或覆盖目标槽位。

备份写入失败时可以在内存读取进度，但禁止自动覆盖原始文件；后续保存必须先成功完成备份。界面明确提示导出进度。槽位列表为只读操作，坏档也可原样导出。导入先验证，再备份被覆盖文件；无效导入不修改槽位。

## 设置

仅保留场景动效、面板毛玻璃、音效开关和音量。公司名称单独修改并保存。设置不影响收益、时间速度或解锁。手动覆盖、读取、删除与重新开始均使用游戏内确认面板；弹窗支持 Escape、Tab 焦点循环及关闭后焦点恢复。

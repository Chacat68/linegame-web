# 十八级公司成长

公司共 18 级，必须从当前级逐级提升。每次操作仅扣除当前级到下一级的费用，不能指定最高级或批量升级；界面提交的等级已变化时，旧操作失败且不再扣款。升级面板显示“当前级 → 下一级”、本次费用与新增研发资格，发展路线默认折叠。

每级开放 2–5 项科技的研发资格，共 65 项，研发完成后才获得船型、船位、功能或属性能力；详见[科技研发](04_科技研发.md)。升级费用按各阶段最大已解锁船队并行经营的实际净利递增，升级和研发分别计费。

每次实验运行 60 分钟，所有船都分配商路并划拨完整货本；任务持续经营，每分钟查看已解除的任务并补派。船队共享同一份港口供货与需求，不将单船净利直接乘上船数。每分钟净利已扣采购货物和完整往返费用，属性与收益科技按真实规则作用于新航次。

## 前期与探索

先看首航回款并积累首次升级资金。Lv.2 船位已满时，提示研发船位规划（100 CR）；完成后再备齐购船 336 CR 与满载矿石货本 162 CR，安排第二条商路。准备 Lv.6 时，引导同时算入新港勘察研发 420 CR 与探索 360 CR；升级后提供进入研发的按钮。完成研发产生首次信号，派空闲船完整往返才开放星云工厂。Lv.12 研发远域勘察后，且星云工厂已开放，45–90 秒后出现原料港信号，探索另需 1,800 CR。

当前固定双船建议策略从 1,000 CR 和一艘轻舟起步，18 秒首航回款，515 秒（8 分 35 秒）升到 Lv.2，549 秒（9 分 9 秒）完成船位规划，755 秒（12 分 35 秒）购买第二艘轻舟并出发。1,286 秒（21 分 26 秒）升到 Lv.3，4,321 秒（72 分 1 秒）升到 Lv.6 并完成新港勘察，4,338 秒（72 分 18 秒）首次探索出发，4,399 秒（73 分 19 秒）开港。仅研发船位规划和新港勘察，共 520 CR。记录见[单船开局前期节奏](单船开局前期节奏.json)，命令为 `npm run simulate:early -- --write`。这条双船路线用于核对现有建议流程，满编实验另包含当级全部科技。

新的完整成长实验使用同样的真实初始资源，每 10 秒主动查看，先研发当级科技、买满当级基础和扩容船位并划拨货本，再逐级升级。全程保留已购船，探索先解除原船贸易并等完整返港；没有赠送资源或直接添加现金。5.83 分钟首次升级，55.33 分钟到 Lv.6，59.67 分钟开通星云工厂，267.33 分钟到 Lv.12，275.17 分钟开通极光原料港，721.00 分钟到 Lv.18，735.50 分钟完成满级 45 艘船与全部 65 项研发。

该路线分别支付公司升级 1,056,300 CR、研发 148,890 CR、购船 51,274 CR、探索 2,160 CR，最终 14,063 CR 的全船队货本另行占用；账本已校验初始资金、净利、全部支出与在途资金守恒。完整 18 级规模和投入见[单船开局满编成长](单船开局满编成长.json)，命令为 `npm run simulate:growth:full -- --write`。这是固定种子与主动投资策略的实验，不含玩家阅读操作时间；此前不扩船的三船实验保留为历史对照。当前价格下另做三船对照：只研发必要船位与功能的路线 1,585.77 分钟到满级，全部科技路线 1,254.07 分钟到满级、1,271.87 分钟完成研发，均比持续补满船队慢。记录见[单船开局三船对照](单船开局三船对照.json)，旧命令 `simulate:growth` 和 `simulate:growth -- --with-research` 保留此低运力策略，模拟窗口延长到 36 小时以覆盖当前费用。

## 旧存档迁移

v27 及更早的六级进度映射为 1→3、2→6、3→9、4→12、5→15、6→18。v28 与 v29 不再次转换公司等级。迁移保留旧档已开放的船型与功能，为其补齐对应研发；不改变现有船、货本、任务、在途金额、港口或统计，不发属性加成。

原文先保留迁移备份，v27 使用 `startrader_save_before_v28_<槽位>`，v28 使用 `startrader_save_before_v29_<槽位>`。损坏或未来版本存档拒绝覆盖；研发及方案移除的具体兼容规则见[科技研发](04_科技研发.md)。

科技细分后的存档结构为 v31，旧属性研发展开为对应完整分组，保持已购买的加成。已有等级不回退，已付款升级不补扣或退费；之后仅按当前等级的新费用继续逐级提升。

当前结构仍为 v32。v31 及更早迁移时仍补齐对应等级已经获得的扩容研发，不扣款、不赠船；未来等级的扩容仍需付费。v32 档只恢复实际完成的研发，已迁移项目不重复显示或扣费。基础船位统一采用当前平衡表，未使用的旧基础船位随之减少；已有船只、任务、周转货本、在途快照和收益保留。若船数超过新上限，界面显示超额数量并禁止添购，现有船继续正常经营；之后升级或研发扩容可增加上限。

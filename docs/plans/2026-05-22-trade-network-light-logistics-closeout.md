# 商网轻物流二阶段收口计划

> 日期：2026-05-22  
> 目标：把贸易站角色、区域协同、策略推荐和下一笔动作收成一个可验收的 P3 小闭环。  
> 架构：只在现有贸易站与商业终端内闭合，不引入库存流、订单簿或后台物流模拟。  
> 技术栈：Vanilla JS、Vitest、现有 `TradeStationSystem` / `MarketUI`。

---

## 1. 当前基线

- 已有站点角色：补给站、枢纽站、科研联络站。
- 已有区域协同：补给商贸环、研发变现链、三角商网。
- 候选与已建站点已经能展示角色和协同收益。
- 已完成：策略推荐、下一笔商网动作的首批规则和回归测试。
- 待完成：收口文档同步、跨系统联动总验收和完整 UI 体验复核。

## 2. 收口范围

- 保留：
  - 派生角色，不写入存档。
  - 同星系组合收益，不做跨星系物流。
  - UI 解释收益来源。
  - 商业终端的一条下一步建议。
- 不做：
  - 真实库存流。
  - 自动运输队列。
  - 站点订单簿。
  - 玩家间市场或动态供应链。

## 3. 实施步骤

1. 完成“商网站点策略推荐计划”。
2. 完成“商业终端下一笔商网动作计划”。
3. 更新 `docs/plans/2026-05-20-next-design-evaluation.md`，将 P3 首批状态改为“已闭合”。
4. 更新 `docs/design/MVP路线图.md` 中 P2 / 中后期经营目标口径。
5. 增加一条端到端回归：有勘探报告、建站候选、区域协同、下一步动作同时出现。
6. 跑完整 `npm test`，记录测试数量和已知非阻塞警告。

## 4. 测试计划

- `tests/tradeStation.test.js`
  - 区域收益、策略推荐、下一笔动作各自有纯规则测试。
- `tests/marketUiFocus.test.js`
  - 商网页展示角色、策略推荐和下一笔动作。
- `tests/guidanceSystem.test.js`
  - 行动条商网建议不重复已经在商业终端内完成的动作。

## 5. 验收

- P3 的三个玩家问题都有答案：
  - 这个站是什么角色。
  - 为什么这个区域组合更赚钱。
  - 下一笔钱该投到哪里。
- 文档明确“不做完整物流模拟”。
- 完整测试通过。

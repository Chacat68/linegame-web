# 行动引导与新手后 30 分钟体验设计

> 日期：2026-05-13  
> 范围：行动建议、统一命令按钮、新手后续节奏、非阻塞引导规则  
> 当前基线：项目已有 `GuidanceSystem`、`ActionGuideUI`、`CommandAction` 与 `SurfaceManager` 的初步实现，本文用于固定产品规则和验收口径。

## 1. 目标

当前游戏已经具备贸易、探索、任务、舰队、金融、商网等主系统。玩家真正缺少的不是更多入口，而是：

1. 当前最值得做什么。
2. 为什么现在做这件事。
3. 点击后会去哪里。
4. 做完后下一步如何继续。

本设计的目标是建立一套轻量、非阻塞、可测试的行动引导层，让新手完成教程或跳过教程后，能在前 20-30 分钟内稳定经历：

1. 接第一张贸易任务。
2. 打开市场并买入低价货。
3. 找到卖出目的地。
4. 完成第一笔贸易。
5. 接探索任务。
6. 扫描当前星球，并理解探索和贸易之间的关系。

这套系统不是新的教程系统，也不是任务脚本引擎。它是运行时“当前行动建议”层，负责把已有系统的下一步动作压缩成一个清晰 CTA。

## 2. 设计选择

### 推荐方案：底部行动条 + 统一命令反馈

行动建议显示在底部导航上方，作为非阻塞的当前行动条。它只展示一个主建议，包含标题、原因和主按钮。按钮执行后，通过统一日志反馈说明已打开哪个 surface、下一步是什么、如何返回。

优点：

- 不打断玩家，不抢 modal 层。
- 能复用当前 `GuidanceSystem.getCurrentSuggestion()`、`ActionGuideUI.render()` 和 `CommandAction.buildCommandFeedback()`。
- 适合测试：输入 state 和 UI context，输出唯一 suggestion。

代价：

- 一次只能推一个动作，复杂决策需要通过优先级压缩。
- 文案必须足够具体，否则玩家仍会迷路。

### 备选方案 A：强化任务面板推荐

把所有引导都塞进任务页，让任务页成为唯一目标中心。

不推荐原因：任务页会继续变重，也无法覆盖市场、扫描、卖货目的地、派遣等非任务动作。

### 备选方案 B：重做教程脚本

用脚本化教程覆盖交易、探索、派遣、金融等系统。

不推荐原因：成本高，且会和已有 `TutorialSystem`、任务推荐、行动建议产生三套引导口径。

## 3. 核心原则

1. **不强制切页**：除非用户点击行动按钮，否则系统不主动打开市场、任务或机库。
2. **不堆多个建议**：任何时刻最多一个主建议；次要建议留在对应业务页内部。
3. **先解除阻塞，再推荐成长**：燃料不足、货舱有货、任务已接但未推进等状态优先于接新任务。
4. **操作后给返回路径**：每次跨 surface 动作都要告诉玩家下一步和返回点。
5. **教程期不竞争**：`TutorialSystem` 激活时，行动条应隐藏或只展示教程认可的动作。
6. **建议可解释**：每条 suggestion 必须有 `reason`，不能只有按钮。
7. **规则可测试**：新增建议必须有优先级和至少一个状态输入测试。

## 4. 用户体验流程

### 4.1 教程完成或跳过后的交接

教程结束后不再自动打开任务面板，也不立即弹出公司命名 modal。系统只做三件事：

1. 写入一条日志：提示底部行动条会继续给下一步建议。
2. 显示行动条：推荐接取“初次交易”。
3. 保留公司命名为低压入口：放在机库 / 设置 / 公司摘要内，不作为首个阻塞弹窗。

这样可以避免“刚跳过教程 -> 自动开任务 -> 又弹公司命名”的连续阻塞。

### 4.2 第一笔贸易链

优先级从高到低：

1. 没有进行中任务，且“初次交易”可接：推荐接取。
2. “初次交易”进行中，货舱为空，市场未打开：推荐打开当前市场。
3. 市场已打开，货舱为空，存在低价商品：推荐查看该商品。
4. 货舱有货，当前节点适合卖出：推荐打开市场并聚焦卖出。
5. 货舱有货，当前节点不适合卖出：推荐定位卖货点。
6. 初次交易完成且货舱为空：推荐接取“初探宇宙”。

关键规则：只要货舱仍有货，就不急着推下一任务。先完成卖出闭环，避免玩家带着货物进入探索链。

### 4.3 第一段探索链

探索建议不抢贸易链优先级。只有当贸易闭环不处于阻塞态时，才推荐：

1. 接取“初探宇宙”。
2. 前往任务目标或邻近未访问节点。
3. 对当前可扫描节点执行轨道扫描。
4. 扫描后执行首次着陆。
5. 着陆后调查下一个 POI。

探索链的文案必须强调收益归属，例如“扫描会揭示本地资源、风险和探索机会”，而不是只写“执行扫描”。

## 5. 架构设计

### 5.1 GuidanceSystem

`GuidanceSystem` 是纯规则层。它不读 DOM，不触发 UI，不修改 state。

输入：

- `state`
- `options.marketOpen`
- `options.scanStatus`
- 后续可扩展：`options.activeSurface`、`options.tutorialActive`、`options.blockingModalOpen`

输出：

```js
{
  id: 'open-market-for-first-trade',
  priority: 90,
  title: '打开当前市场',
  reason: '先买入一批商品，才能推进交易目标。',
  actionLabel: '打开市场',
  actionType: 'market.open',
  payload: { workspaceId: 'spot', subworkspaceId: 'trade' },
  surface: 'market'
}
```

建议对象必须保持小而稳定。不要把完整 UI 文案、HTML 或复杂业务结果塞进 suggestion。

### 5.2 ActionGuideUI

`ActionGuideUI` 只负责渲染当前建议。

职责：

- 展示展开态：当前行动、原因、主按钮、折叠按钮。
- 展示折叠态：迷你行动条。
- 把按钮点击回传给 `GameManager`。
- 保持非阻塞，不创建 modal，不吞掉底部导航。

非职责：

- 不计算下一步。
- 不决定能否执行动作。
- 不直接改游戏状态。

### 5.3 CommandAction

`CommandAction` 负责跨模块按钮的统一语言。

它应统一：

- `commandSurface`：市场、任务、探索、航行、机库、科技。
- `commandIntent`：现货交易区、POI 调查、科研补给等。
- `commandVerb`：打开、接取、定位、调查。
- 执行后的日志反馈。

目标是让市场、任务、探索、科研、派遣里的 CTA 看起来属于同一套指挥语言。

### 5.4 GameManager

`GameManager` 是动作执行层。它接收 suggestion，按 `actionType` 分发到已有系统：

- `quest.accept`
- `quest.open`
- `market.open`
- `market.focus`
- `map.focus`
- `exploration.scan`
- 后续扩展：`exploration.land`、`exploration.poi`、`fleet.dispatch.prefill`、`research.open`

每次执行后必须触发 UI 刷新，并重新计算当前 suggestion。

## 6. Surface 与打断规则

行动条应遵守 `SurfaceManager` 的层级规则：

1. Blocking modal 打开时，行动条可隐藏或降级为不可点击状态。
2. Event notification 存在待处理事件时，行动条不得推荐旅行。
3. Market overlay 打开时，市场相关建议可以继续显示，但不重复提示“打开市场”。
4. Secondary overlay 打开时，行动建议不强制关闭当前面板，除非用户点击跨 surface CTA。
5. 玩家手动折叠行动条后，不因普通 UI 刷新自动展开；只有关键阶段切换或新会话可恢复展开。

## 7. 优先级规则

建议优先级采用“阻塞优先、闭环优先、成长随后”的顺序。

| 区间 | 类型 | 示例 |
| --- | --- | --- |
| 100-90 | 新手主链必需动作 | 接取初次交易、打开市场 |
| 89-70 | 当前闭环推进 | 查看低价货、卖出已有货物 |
| 69-50 | 目的地与任务衔接 | 定位卖货点、接初探宇宙 |
| 49-30 | 探索与成长动作 | 扫描、着陆、POI |
| 29-10 | 中期系统入口 | 科研补给、派遣建议、商网投资 |

2026-05-22 中期扩展后，优先级口径补充如下：

- 待处理事件使用最高优先级，必须压过旅行、补给、扫描和派遣，因为事件会阻塞跨界面和航行决策。
- 低燃料补给属于阻塞解除，优先级高于买货、探索、派遣和商网成长。
- 船况维修高于科研补给、派遣、金融和商网投入；维修资金不足时才退回市场周转。
- 货舱有货仍属于未完成闭环，优先级高于金融风险、科研补给、普通派遣和商网经营。
- 勘探情报、金融、批量商网、单站商网和普通派遣都属于中期建议层，必须服从目标达成过滤：如果目标市场 workspace/subworkspace 已经打开，不再重复推荐同一导航动作。

如果两个建议同优先级，按以下顺序打破平局：

1. 正在进行的任务。
2. 当前货舱 / 燃料 / 船况阻塞。
3. 当前 surface 可直接完成的动作。
4. 最近一次玩家主动打开的系统。

## 8. 错误与边界处理

1. suggestion 指向的任务不存在：刷新建议，不执行动作，写入 info 日志。
2. 市场焦点商品不存在：打开市场默认现货页，不中断。
3. 卖货目的地不可达：退回星图，并提示先补燃料或解锁跃迁。
4. 扫描燃料不足：不执行扫描，推荐打开市场补给。
5. 事件待处理：阻止旅行类建议，先引导处理事件。
6. modal 已打开：不自动执行跨 surface 动作。

这些边界都应通过系统返回值或 options 输入处理，不让 UI 层自行猜测。

## 9. 测试计划

### GuidanceSystem

- 无任务时推荐接取初次交易。
- 初次交易进行中且货舱为空时推荐打开市场。
- 市场已打开时推荐聚焦低价商品。
- 货舱有货时优先推荐卖出或定位卖货点。
- 货舱未清空时不推荐接下一任务。
- 扫描建议优先级低于新手贸易链。
- Blocking modal / tutorial active 时不输出普通建议。

### ActionGuideUI

- 能渲染展开态和折叠态。
- 点击主按钮回传 suggestion。
- 无 suggestion 时隐藏根节点。
- processing 状态不会残留到下一条 suggestion。
- 折叠状态在普通刷新后保持。

### CommandAction

- 各 surface 能生成统一 `data-command-*` 属性。
- 统一反馈文案包含 destination、nextStep、returnTo。
- 市场、探索、机库、科技的 kicker 语言一致。

### GameManager 集成

- 点击“接取任务”会进入任务页并接取目标任务。
- 点击“打开市场”会打开指定 workspace/subworkspace。
- 点击“定位卖货点”会聚焦星图目标。
- 点击“执行扫描”会调用探索系统并刷新星球详情。
- 执行后会重新计算下一条 suggestion。

## 10. 验收标准

1. 跳过教程后不会连续自动打开任务面板和公司命名 modal。
2. 新手第一笔贸易链可以只依靠行动条完成。
3. 行动条任何时刻最多展示一个主建议。
4. 所有行动按钮都有统一 command 元信息和反馈文案。
5. 市场、任务、星图、探索之间的跳转都有明确返回提示。
6. 新增或修改建议必须有单元测试覆盖。
7. 桌面与移动视口下，行动条不遮挡底部导航和关键 CTA。

## 11. 非目标

- 不重做 `TutorialSystem`。
- 不新增剧情脚本系统。
- 不做多建议队列。
- 不新增存档字段。
- 不把行动建议扩展成全局 AI 助手。
- 不在本轮设计金融、商网、多人或云存档引导。

## 12. 后续扩展

完成新手后 30 分钟引导后，再逐步纳入：

1. 中期科研补给建议。
2. 任务派遣建议。
3. 商网投资 / 升级建议。
4. 舰船维护和检修建议。
5. 派系关系与黑市准入建议。

扩展时仍遵守一个原则：业务页负责细节，行动条只推当前最值得做的一步。

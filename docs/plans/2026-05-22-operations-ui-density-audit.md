# 经营 UI 信息密度审计计划

> 日期：2026-05-22  
> 目标：整理市场、HUD、地图、机库中重复承载的经营摘要和下一步提示，减少中期界面噪音。  
> 架构：先审计和列删改矩阵，再小步调整 UI；不做整页重构。  
> 技术栈：HTML/CSS、Vanilla JS、Vitest。

---

## 1. 当前基线

- `MarketUI` 承载现货、资本、商网、情报等重入口。
- `HUD` 展示目标摘要和下一步。
- `MapUI` 展示探索、航线、星球详情。
- `FleetUI` 展示维修、派遣、公司和模块。
- 行动条也在展示下一步建议，信息可能重复。

## 2. 审计口径

- 保留一个主入口：
  - 全局下一步归行动条。
  - 商网下一步归商业终端内部。
  - 当前航点探索状态归地图详情和 HUD 摘要。
- 降级重复内容：
  - HUD 只保留摘要，不承载长解释。
  - 市场页卡片只解释当前工作区，不重复教程文案。
  - 地图详情只展示当前星球相关行动，不展示全局经营建议。
- 不改变业务规则，不移动存档字段。

## 3. 实施步骤

1. 建立 UI 信息矩阵文档，列出每个页面展示的“下一步 / 收益 / 风险 / 入口”。
2. 标记重复项：保留、降级、删除、迁移。
3. 优先调整纯文案和展示层，不改系统计算。
4. 对有交互的删改补 UI 测试。
5. 做一次桌面宽度和移动宽度人工检查。

## 4. 测试计划

- `tests/hudSummary.test.js`
  - HUD 保持摘要字段。
- `tests/marketUiFocus.test.js`
  - 市场 / 商网页关键 CTA 仍存在。
- `tests/mapUiScanCard.test.js`
  - 地图探索入口仍存在。
- 视觉验证：
  - 本地服务启动后检查市场、地图、机库三页无明显文字重叠。

## 5. 验收

- 用户不会在三个位置看到互相冲突的“下一步”。
- 每个页面只解释自己能直接执行的动作。
- 行动条作为全局建议层保持清晰。

# 舰队经营 2.0 设计说明

## 目标

- 在不引入战斗、乘客或大型技能树的前提下，给现有多船系统增加经营压力。
- 让舰队扩张不仅是堆数值，还要考虑维护、分工和模块化定位。
- 复用当前 FleetSystem、CrewSystem、ShipSpecialization 与自动派遣链路，避免新增一套平行状态机。

## 本次实现范围

### 1. 舰船维护度

- 每艘船新增嵌套字段：`maintenance`、`lastServiceDay`、`faults`。
- 维护度范围为 0 到 100，保持在 `ship` 对象内部，不扩展顶层存档结构。
- `faults` 为轻量故障列表，默认空数组，仅在重度失养或欠费压力下生成。
- 旧存档在 `Fleet.init` 中自动补齐，默认维护度为 100，故障列表为空。

### 2. 日常养护结算

- `GameTime.advanceDays` 现在会调用 `Fleet.advanceFleetDay`。
- 每日结算包含：
  - 舰船日常养护费。
  - 维护度自然衰减。
  - 派遣中的额外损耗。
  - 低维护或欠费导致的额外磨损。
  - 严重失养或欠费压力下触发轻量故障。
  - 全舰队自动修复的日结应用。

### 3. 航行磨损

- 玩家主动航行和非激活船只的派遣航行都会调用 `Fleet.applyTravelWear`。
- 磨损由以下因素共同决定：
  - 航行类型。
  - 燃料消耗。
  - 当前载货压力。
  - 船型维护衰减倍率。
  - 改装提供的维护损耗修正。
  - 舰船分工带来的磨损抗性。
  - 已存在故障带来的额外磨损倍率。

### 4. 维护度对实际表现的影响

- 维护度不会直接改写基础船体数值，而是通过 `getEffectiveShipStats` 影响派生表现。
- 当前已接入的影响项：
  - 燃耗。
  - 随机事件概率权重。
  - 自动修复效率。
  - 走私检查压力。
  - 有效货舱。
  - 扫描折扣利用率。

### 5. 检修动作

- 新增 `Fleet.serviceShip`。
- 检修扩展为三级：
  - 快速保养：低成本恢复部分维护度，不清除故障。
  - 深度坞修：完全恢复维护度，清除全部故障，并修复部分船体。
  - 应急抢修：可在派遣中执行，恢复部分维护度，并清除 1 项故障。
- 检修花费基于当前维护缺口、船体缺口与故障数量计算。
- 后勤维护分工会进一步降低检修成本，并提高快速保养 / 应急抢修的恢复量。
- UI 侧在机库卡片上提供维护入口，并在弹窗中展示三种方案。

### 6. 轻量故障层

- 故障不单独建系统，仍作为 `ship` 对象上的嵌套状态存在。
- 当前已实现三类故障：
  - 引擎振荡：燃耗上升，航行磨损加剧。
  - 传感盲区：事件压力上升，扫描折扣变弱。
  - 货舱卡滞：有效货舱下降，卖出议价变差。
- 故障效果统一通过 `getEffectiveShipStats` 和 `applyTravelWear` 接入，避免在 UI 或业务分支里额外打补丁。
- 分工会对故障产生差异化抗性：
  - 快航中继减轻引擎振荡的燃耗与磨损惩罚。
  - 勘探支援减轻传感盲区对事件压力与扫描折扣的负面影响。
  - 主力商运减轻货舱卡滞的容量与议价损失。
  - 后勤维护降低故障触发率，并强化恢复倾向。

## 功能型改装

本次新增三种“分工型”模块，而不是继续堆纯数值模块：

- `mod_service_bay`
  - 目标：后勤维护。
  - 效果：自动修复 +1，维护损耗 ×0.75。

- `mod_smuggler_hold`
  - 目标：灰市运输。
  - 效果：走私检查率 ×0.78，罚款 ×0.85。

- `mod_survey_array`
  - 目标：勘探支援。
  - 效果：扫描燃料 -20%，勘探收益 +12%。

同时，船型和模块都增加了日常养护费字段，用于日结成本核算。

## 舰队分工

- 新增 `Fleet.getShipRoleProfile`，基于以下信息推导舰船主职能：
  - 船型。
  - 当前 doctrine。
  - 已安装改装。
  - 船员 specialty。
- 当前角色类型：
  - 主力商运
  - 快航中继
  - 勘探支援
  - 灰市突破
  - 后勤维护

该画像现在同时参与：

- 维护衰减与故障触发倍率。
- 检修恢复量与部分检修成本。
- 故障惩罚的角色化抗性。
- 自动派遣推荐的路线偏好、风险修正与策略说明。
- 激活船任务派遣中的任务路线择优与策略摘要。
- 研究页中的科研补给建议与相关货运方向推荐。

## UI 改动

机库卡片新增：

- 舰船分工标签。
- 维护状态标签。
- 日常养护费。
- 预计日损耗。
- 故障标签。
- 维护按钮与维护调度弹窗。

原则上仍沿用现有卡片结构，只增加一个轻量维护弹窗，不重做机库页布局。

## 系统耦合点

- `FleetSystem`
  - 新增维护度与分工核心逻辑。
- `GameTimeSystem`
  - 接入日结养护。
- `GameManager`
  - 玩家航行后追加磨损。
  - 暴露检修 handler 给 UI。
- `FleetUI`
  - 呈现维护/分工，并提供检修动作。
  - 在派遣弹窗中展示角色策略说明与船况压力提示。
- `MapUI`
  - 通用“打开市场”入口现在会按当前节点上下文自动给出默认落点：常规补给回到现货交易，研究型节点优先落到市场情报，已解锁黑市的特殊节点优先落到黑市分区，当前节点若已有站点或本地投资则优先落到本地节点经营。
  - 探索简报现在会直接渲染一个市场 CTA，复用同一套 market focus preset，并通过 `data-exploration-action="market"` 走统一动作总线，支持从当前或悬停节点直接跳到对应市场子页。
  - 探索简报 CTA 会附带一条轻量上下文提示，直接解释为什么这次落到现货交易 / 市场情报 / 黑市 / 本地经营，而不是只显示目标子页名。
- `AutoTradeSystem`
  - 接入派遣画像，对查获风险和路线评分做差异化调整。
  - 任务路线推荐会吸收派遣画像，返回策略摘要。
  - 新增 `findResearchSupplyRoute`，为研究页提供科研补给建议。
- `DispatchController`
  - 激活船任务派遣每 tick 按派遣画像刷新任务路线选择。
- `ResearchUI`
  - 渲染科研补给建议卡，展示当前研究或候选方向对应的推荐补给线。
  - 支持从科研补给建议一键切到机库，并预填派遣弹窗中的买卖地、商品与市场策略。
  - 当当前研究方向因资金、舱位或可达补给点不足而无法生成科研补给建议时，渲染 blocker 卡，并提供主动作与次动作。
  - 研究页 blocker 的市场主动作会按原因直接落到商业终端的现货交易、资本调度或本地节点经营子入口，而不是只打开市场首页。
  - 研究页 blocker 的次动作复用任务页的 fallback copy 规则，但会按资金/舱位语义改写提示，避免把研究场景误写成“补燃料”。
- `FactionUI`
  - 派系卡现在会渲染代表市场 CTA。普通派系默认打开代表节点市场，辛迪加在未解锁时导向暗影港湾的公开情报入口，解锁后直接导向黑市分区。
  - 派系 CTA 下方会显示“代表节点 + 落点原因”，例如农业节点优先现货、辛迪加未解锁时先看情报与准入门槛。
- `QuestUI`
  - 对当前最优的进行中任务渲染任务派遣建议卡，并支持一键带入机库派遣。
  - 当当前任务因等级、跃迁科技或燃料等原因暂不可执行时，渲染阻塞原因卡，明确说明为什么此时不生成派遣建议。
  - 任务页 blocker 的市场主动作会按原因直接落到商业终端的现货交易子入口，避免只打开市场默认页后还要再找补给或跑单入口。
  - 阻塞原因卡升级为主动作 + 次动作：主动作继续负责跳到科技页或当前市场解除阻塞，次动作负责把任务页聚焦到一条当前更适合推进的可接任务，减少玩家卡关时的切换成本。
  - 次动作文案不再使用统一 copy，而是按 blocker 原因和 fallback 任务形态做轻量分流，例如“先补等级”“先做本地任务”“先跑短线补给”。
- `ships.js`
  - 船型维护配置与新增功能型改装。

- 科研补给建议到机库派遣弹窗的一键带入链路。
- 科研页在“无科研补给建议”时对 blocker 卡、市场主动作和任务页次动作的渲染与跳转。

- 任务页 blocker 卡 CTA 对科技页 / 市场页的跳转引导。
- 任务页 blocker 卡的双动作联动：主动作解除阻塞，次动作聚焦推荐可接任务。

- 商业终端共享 market focus helper 对默认市场入口的上下文落点：现货交易 / 市场情报 / 黑市分区 / 本地节点经营。

- 更细粒度的派遣策略联动，例如把角色偏好继续拆到任务派遣、科研补给和跨星系跃迁选择。

## 2026-05-24 追加收口：功能型改装推荐

- `Fleet.getShipModRecommendation()` 已基于维护压力、船体缺口、故障、舰船分工、专精协议、载货压力和当前派遣模式给出单项推荐。
- 机库卡片会显示推荐组件摘要，改装弹窗会展示推荐理由、安装按钮和当前阻塞原因。
- 行动引导会在没有更高优先级阻塞时提示可安装的推荐组件，并通过 `fleet.mod.open` 切到机库让玩家确认。
- `fleet.mod.open` 会携带推荐组件 ID 打开模块改装视图，机库弹窗会高亮并滚动到对应组件，减少从建议到安装之间的查找成本。
- 机库改装视图会向行动引导暴露当前舰船和推荐组件上下文；当同一组件已经打开时，行动条不再重复提示同一条推荐。
- 成功安装改装后会用一次性上下文跳过同舰船的后续改装提示，让行动条立即转向派遣、经营或其它下一步建议。
- 行动条新增短暂完成态；推荐改装安装成功后会显示“已安装”，随后恢复到已刷新的下一条建议。
- 完成态已扩展到补给、维修、派遣草案载入、派遣确认和市场/星图定位；派遣弹窗会暴露当前路线草案，避免同一路线预填被行动条重复推荐。
- 推荐仅复用现有组件，不新增改装系统；当前覆盖后勤维护、勘探支援、灰市突破、快航中继和主力商运几类典型定位。

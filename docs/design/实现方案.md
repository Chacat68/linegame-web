## 三、关键差异与决策

### 3.1 存档介质差异

设计文档目标：IndexedDB  
当前实现：localStorage（4 槽位 + `schemaVersion`）

**决策建议（短期）**

- 先保持 localStorage，优先完成契约冻结与迁移函数规范。
- 当单存档体积或存档频率成为瓶颈时，再迁移到 IndexedDB。

### 3.2 “功能开发”转“质量建设”

当前最大风险不是“缺系统”，而是：

- 文档口径落后，团队沟通成本高
- 数值参数分散，平衡调整代价高
- 缺少最小自动回归，改动后容易出现隐性回退

## 四、分阶段行动计划

## 阶段 A（本周）— 文档与契约统一

### A1. 文档统一

- 更新 `设计实现对照表.md`（已执行）
- 更新 `README.md` 与 `MVP路线图.md` 的路径口径（`js/` 优先）
- 明确“已实现 / 部分实现 / 未实现”三态，不再使用过期结论

### A2. GameState 与 SaveEnvelope 冻结

- 固化核心字段清单与默认值来源
- 约定 `schemaVersion` 递增规则
- 明确“新增字段必须提供迁移补丁”

当前落地规则（2026-04-10）：

- `js/data/constants.js` 中的 `SAVE_STATE_SCHEMA` 是持久化字段与默认值的唯一真理来源。
- `PERSISTED_STATE_DEFAULTS` 代表入档默认态；`RUNTIME_ONLY_FIELDS` 明确哪些字段只存在于运行时、不进入存档。
- `createInitialState()` 基于同一契约生成运行态，`tests/helpers.js` 通过它构造测试状态，避免测试夹带过期字段结构。
- 新增持久化字段时，必须同步更新 `SAVE_STATE_SCHEMA`、对应默认值、迁移链和至少一个回归测试；仅运行时字段则必须加入 `RUNTIME_ONLY_FIELDS`。
- `schemaVersion` 只允许向前迁移；遇到高于当前 `SAVE_SCHEMA_VERSION` 的未来存档，必须拒绝加载而不是静默降级。

### A3. 存档策略说明

- 记录 localStorage 当前上限与适用边界
- 补充 IndexedDB 迁移触发条件（非立即实施）

当前策略（2026-04-10）：

- 继续维持 localStorage 四槽位方案，因为当前存档模型仍以结构稳定和迁移安全为第一目标。
- 导入、读档、迁移均以 `SaveEnvelope(meta + data)` 为边界，异常 JSON、坏 meta、缺字段和旧版本迁移都必须有明确定义。
- 只有当单槽位体积、写入频率或跨设备同步成为真实瓶颈时，才启动 IndexedDB 或云存档迁移；在此之前优先保证 schema 规则和回归集稳定。

## 阶段 B（1-2 周）— 平衡与体验稳定

### B1. 经济参数配置化

将以下参数从逻辑中抽离到可调配置：

- 供需回弹系数
- 峰值事件触发概率
- 税率修正区间
- 科技/派系乘区顺序（确保可预期）

当前口径（2026-03-18）：

- 关键参数已集中在 `js/data/constants.js`
- 经济系统使用 `ECONOMY_CONFIG`
- 派系关系与交易影响使用 `FACTION_CONFIG`
- 等级奖励使用 `PROGRESSION_CONFIG`

当前价格计算顺序约定：

1. 基础价格 × 星系价格倍率 × 每日波动修正
2. 叠加供需修正
3. 叠加经济周期修正
4. 叠加产业链修正
5. 应用买入/卖出基础乘数
6. 应用派系税率修正
7. 应用科技与等级带来的买入折扣 / 卖出加成
8. 应用当前操控船只与舰队编队带来的贸易加成

说明：

- 买入顺序：`factionTax -> techBuyDiscount -> fleetTradeBonus`
- 卖出顺序：`factionTax -> techSellBonus -> fleetTradeBonus`
- `fleetTradeBonus` 当前包含：激活船只技能、激活船只改装、整支舰队满足编队条件后的交易加成

### B2. 事件分层与节奏

- 事件按游戏阶段分池（新手/中期/后期）
- 同类型事件增加冷却，降低重复感
- 高惩罚事件添加保护阈值（避免新手劝退）

### B3. 引导-任务联动

- 教程结束后自动推荐首批任务
- 将“第一桶金”目标与任务奖励联动
- 减少并发提示，保证信息密度可控

当前状态（2026-03-08）：

- 教程完成后会自动切换到任务页
- 系统会推荐当前阶段已解锁、最适合新手继续推进的 2-3 个入门任务
- 任务面板会对推荐任务显示显式标记，降低教程结束后的目标不明确问题

## 阶段 C（2-4 周）— 质量与可维护性

### C1. 最小回归集

优先覆盖三类高风险逻辑：

1. 存档：保存→读取→迁移
2. 经济：买卖价格与供需更新
3. 任务：触发、推进、结算

### C2. 状态修改边界收敛

- 约束 UI 层只发动作，不直接改核心状态
- 将复杂状态变更集中在系统层函数
- 逐步减少 `GameManager` 体积与耦合

### C3. 可观测性

- 关键动作打点（交易、旅行、任务、存档）
- 引入简单调试开关（开发模式日志增强）

## 六、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 文档继续滞后 | 新成员理解偏差 | 每次版本发布同步更新对照表 |
| 数值调整无基线 | 体验波动大 | 建立参数配置 + 调整记录 |

| 大模块持续膨胀 | 修改成本上升 | 逐步拆分动作域与状态域 |

# 星际贸易商 - 已实现 / 部分实现 / 未实现清单

> 更新日期：2026-04-10  
> 判定基准：以当前仓库 `js/`、`ui/`、`tests/` 实际代码与主循环接线为准，不以历史文档或已删除模块为准。  
> 状态说明：`✅ 已实现` = 已接入主循环或运行时可用；`🔶 部分实现` = 有代码但存在明显缺口、占位、未完全接线或只完成骨架；`❌ 未实现` = 设计文档存在，但仓库内没有对应模块或没有运行时能力。

---

## 0. 总览

当前项目已经不是“只有设计文档”的阶段。核心贸易闭环、经济、事件、派系、科技、任务、成就、胜利、舰队、船员、金融、贸易站、存档、3D 星图都已落地。

目前真正的缺口主要集中在三类：

1. 设计文档里体量很大的远期系统：音频、多人联网、真正的 i18n。
2. 已有骨架但深度不足的系统：探索、星系数据层、飞船高阶能力、剧情演出。
3. 资产与商网的高级调度体验仍不足：贸易站经营虽已并入 `MarketUI.js`，`CommerceFacade.getCommerceSnapshot()` 也已补齐，商网总览也支持批量投资 / 升级 / 经理 / 策略指令，但跨站物流与区域供应链调度仍未展开。

## 1. 核心架构与状态管理

### ✅ 已实现

- `js/core/GameManager.js` 持有单一 `_state`，负责系统初始化、动作分发、UI 同步、自动存档。
- `js/core/EventBus.js` 已覆盖日志、教程、成就、研究等广播场景。
- `js/data/constants.js` 已成为状态结构与存档契约的唯一真理来源；当前 `SAVE_SCHEMA_VERSION = 10`，`GAME_VERSION = 0.6.0`。
- `js/core/SettingsManager.js` 已接入显示、难度、数据管理设置。
- `js/systems/commerce/CommerceFacade.js` 已作为市场、金融、贸易站动作的统一入口，并被 `GameManager` 实际调用。

### 🔶 部分实现

- `CommerceFacade.getCommerceSnapshot()` 设计上要提供统一商业快照，但其中依赖的 `Futures.getFuturesSnapshot()` 并不存在，接口完成度不足。
- `GameManager.js` 仍然承担了过多编排职责，系统调度、动作处理、UI 刷新集中在单文件中，可维护性一般。

### ❌ 未实现

- 统一资源管理器（图片、音频、资产预加载）
- 独立网络同步层
- 独立国际化服务层

## 2. 贸易与经济系统

### ✅ 已实现

- `TradeSystem.js` 已完成买入、卖出、燃料补给、旅行、跨星系跳跃判定、货物成本追踪、利润统计。
- `Economy.js` 已实现供需、价格漂移、市场深度、价格历史、经济周期、黑市价格、走私检查。
- `MarketUI.js` 已提供现货页、价格矩阵、行情图表、K 线化展示、市场分析面板。
- `Trade.travelTo()` 已在旅行时联动推进 `Economy.advanceDay()`、`TradeStation.advanceDay()`、`Finance.advanceDay()`。

### 🔶 部分实现

- “市场深度”当前主要用于价格模型和指标展示，还不是一个可交互的订单簿或撮合系统。
- 商业终端虽然已经把现货、资本、经营整合到一起，但整体仍偏单机经营面板，没有更复杂的市场结构。

### ❌ 未实现

- 玩家间交易市场
- 拍卖行 / 委托单 / 订单簿撮合

## 3. 金融与资本系统

### ✅ 已实现

- `FinanceSystem.js` 已实现贷款、信用评级、股票、贸易站追加投资、保险、理赔、日结分红。
- `FuturesSystem.js` 已实现多头/空头合约、保证金、到期结算、手动平仓、浮动盈亏计入净资产。

### ❌ 未实现

- 玩家间金融市场
- 委托交易 / 拍卖 / 订单撮合

## 4. 贸易站与商网经营

## 6. 星图、星系与探索系统

### ✅ 已实现

- `data/systems.js` 已生成多星系、多星球数据，并有等级解锁与跨星系旅行门槛。
- `Renderer3DAdvanced.js` 已成为当前唯一有效的 3D 星图渲染入口，支持星球视图、星系视图、飞船飞行动画、派遣航线可视化。
- `MapUI.js` 已完成 3D 交互、市场打开、星系/星球视图切换、悬停详情。
- `GalaxyDataLayer.js` 已提供星系层次数据、星球运行时状态、批量状态更新接口，并参与存档读写。
- 探索进度已体现在已访问星球/星系、探索任务、探索成就、探索类胜利条件上。

### 🔶 部分实现

- 探索玩法目前主要是“旅行到达 + 访问计数 + 任务/成就/事件文本”，还没有形成独立的扫描、着陆、POI 发现、遗迹发掘闭环。
- `GalaxyDataLayer.js` 已有 `updatePlanetState()`、`batchUpdatePlanetStates()` 等接口，但当前主要被渲染器和存档使用，真正驱动玩法状态变化的接线还不多。
- 设计文档中的“隐藏区域、秘密航线、探索点、着陆点类型、星球设施互动”大多仍停留在设定层。

### ❌ 未实现

- 独立扫描系统
- 隐藏区域 / 秘密航线发现机制
- 着陆许可、着陆点选择、着陆费用系统
- 遗迹 / 资源站点 / 探索点的专门玩法界面

## 19. 结论

如果按“当前能不能玩、核心系统是否接线”来判断，项目的大部分核心玩法已经实现。

如果按设计文档的完整蓝图来判断，当前最主要的“部分实现 / 未实现”集中在：

1. 探索深化不足：探索 MVP 已形成扫描 / 着陆 / POI / 秘密航线闭环，但更复杂的遗迹链、隐藏区域和专属事件分支仍未展开。
2. 飞船高阶玩法不足：已有舰队 / 改装 / 船员，但没有战斗、乘客、外观等大系统。
3. 剧情演出不足：已有章节任务和事件文本，但没有对话树 / 剧情演出引擎。
4. 远期平台能力未做：音频、多人、i18n、云存档都还没开始。

### 建议的文档口径

- 对外可以明确表述为：“核心单机贸易经营版已实现；探索深化、音频、多人、国际化属于后续阶段。”
- 不再使用旧文档里 `Renderer.js`、`IndexedDB 已实现`、`TradeStationUI 独立可用` 这类已经过时的说法。

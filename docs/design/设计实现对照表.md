# 星际贸易商 - 已实现 / 部分实现 / 未实现清单

> 更新日期：2026-08-17
> 判定基准：以当前仓库 `js/`、`ui/`、`tests/` 实际代码与主循环接线为准，不以历史文档或已删除模块为准。
> 状态说明：`✅ 已实现` = 已接入主循环或运行时可用；`🔶 部分实现` = 有代码但存在明显缺口、占位、未完全接线或只完成骨架；`❌ 未实现` = 设计文档存在，但仓库内没有对应模块或没有运行时能力。

---

## 0. 总览

当前项目已经不是“只有设计文档”的阶段。核心贸易闭环、经济、事件、派系、科技、任务、成就、胜利、舰队、船员、金融、贸易站、存档、3D 星图都已落地。全量经济审计已完成，价格优惠共享递减上限、贸易站回本曲线、五条胜利路线量化门槛均已验收。

本轮（2026-08-17）状态：
- ✅ 中期专题教学链（`MidgameTeachingChain.js`）：4 条专题链已具备主动启动入口、建议提权、真实动作推进、派遣循环基线、单链并发约束和 v17 持久化
- ✅ 本地平衡统计：`BalanceMetricsSystem` 随存档只在本设备记录；设置页可导出脱敏 JSON 审查，不会自动上传，也不再展示无效的采集同意开关
- ✅ 当前版本、存档与测试口径已核对：`GAME_VERSION = 0.6.4`、`SAVE_SCHEMA_VERSION = 17`，全量测试为 136 个文件、1173 项

目前真正的缺口主要集中在三类：

1. 设计文档里体量很大的远期系统：完整音频平台、多人联网、真正的 i18n。
2. 已有 MVP 但仍需深化的系统：探索深化（遗迹链/异常点）、飞船高阶能力和剧情演出。
3. 资产与商网的高级调度体验仍不足：贸易站经营虽已并入 `MarketUI.js`，`CommerceFacade.getCommerceSnapshot()` 也已补齐，商网总览也支持批量投资 / 升级 / 经理 / 策略指令，但跨站物流与区域供应链调度仍未展开。

## 1. 核心架构与状态管理

### ✅ 已实现

- `js/core/StateSession.js` 持有 state/revision/token；`GameApplication.js` 是正式组合根并持有迁移期 `_state` 镜像与受限 Runtime Graph，`GameManager.js` 仅重导出历史公共 API。
- `js/core/EventBus.js` 已覆盖日志、教程、成就、研究等广播场景。
- `js/data/constants.js` 已成为状态结构与存档契约的唯一真理来源；当前 `SAVE_SCHEMA_VERSION = 17`，`GAME_VERSION = 0.6.4`。
- `js/core/SettingsManager.js` 已接入显示、难度、数据管理设置。
- `js/core/GameFeatureRuntime.js` 已把 `FeatureRegistry` 与 `GameFeatureManifest` 组合成唯一已配置端口，统一市场、舰队、档案、存档、胜利、设置、教程、引导、经营/路线/成就、剧情和随机事件模块的依赖、按需加载、会话同步、失败重试与释放。
- `js/core/GameUiApplicationRuntime.js` 已统一 MarketWorkspace、Settings、GameUiCoordinator、GameUiLifecycle 与 Context adapters 的延迟组装、latest-state/session providers、入口呈现、增量刷新、复合 diagnostics 与释放端口。
- `js/core/GameLoopRuntime.js` 已统一实时日、场景帧、延迟功能/DOM/教程暂停、领域日推进与 active-dispatch 周期任务；`GameManager` 不再直接持有 RAF、recurring id 或暂停选择器。
- `js/core/GameApplicationLifecycle.js` 已统一应用级 shutdown 顺序、失败隔离和幂等语义；页面退出与 HMR 共用该入口，Context/Feature/Renderer 均有真实释放路径。
- `js/core/GameRuntimeGraph.js` 已统一 12 个应用 runtime 节点的惰性构造、循环依赖保护、失败重试、generation 诊断与引用清理。
- `js/systems/commerce/CommerceFacade.js` 已作为市场、金融、贸易站动作的统一入口，并被 `GameManager` 实际调用。

### 🔶 部分实现

- `GameManager.js` 已从约 2,900 行收束为 16 行兼容门面，`main.js` 直接依赖正式 `GameApplication`；当前 724 行 `GameApplication` 的 12 个节点已全部接入独立 Runtime Graph，但节点工厂声明、Renderer/Settings 启动投影和 7 个测试门面仍需继续拆分。
- 存档契约当前已经以 `SAVE_STATE_SCHEMA` 为唯一来源，但这套约束主要体现在代码和测试中，仍需继续靠文档与回归测试来防止后续字段扩张时重新失焦。

### ❌ 未实现

- 统一资源管理器（图片、音频、资产预加载）
- 独立网络同步层
- 独立国际化服务层

## 5. 飞船、舰队与船员系统

### ✅ 已实现

- `FleetSystem.js` 已支持多船、席位、买船、卖船、切船、升级、改装件、自动派遣航线。
- `CrewSystem.js` 已支持船员市场、招募、分配/撤下、船员专长、日薪、成长与升级。
- 派遣航线、当前航段显示、残留飞线修复逻辑都已有实际运行链路。
- `FleetUI.js` 已提供船队、船员、升级、改装、招募等界面；机库主视图、船坞采购、船员详情、改装/保养详情与自动跑商策略/估算投影已分别迁入 `FleetHangarPresenter.js`、`FleetShopPresenter.js`、`FleetCrewPresenter.js`、`FleetModPresenter.js`、`FleetDispatchPresenter.js`。Hangar/Shop/Crew/Mod 交互由内容根节点单一委托，Dispatch Presenter 保持无 DOM 的纯投影边界。
- `FleetUI.js` 不再读取不存在的全局 `GameManager`；公开渲染与三类弹层统一接收请求对象，并通过 `FleetCommand.js` 的单一 typed command 端口发布买船、切船、升级、改装、船员和派遣动作；内联详情关闭和售船后的重绘由 `GameUiCoordinator` 注入 latest-state `requestRender` command。

### 🔶 部分实现

- 设计文档里的“飞船特殊技能树”“护盾/武器/乘客舱/外观改装”等高阶能力，目前只部分折算为船体数值、改装件和船员加成，没有形成完整子系统。
- 飞船高级玩法当前聚焦在货舱、燃料、船体、改装、派遣、船员；没有完整的战斗化或外观自定义化路线。

### ❌ 未实现

- 飞船战斗系统
- 乘客运输系统
- 外观涂装 / 标识自定义
- 独立的护盾 / 武器能源战斗模型

## 19. 结论

如果按“当前能不能玩、核心系统是否接线”来判断，项目的大部分核心玩法已经实现。

如果按设计文档的完整蓝图来判断，当前最主要的“部分实现 / 未实现”集中在：

1. 探索深化不足：探索 MVP 已形成 POI / 秘密航线 / 勘探报告闭环，但更复杂的遗迹链、隐藏区域、专属事件分支和经营联动仍未展开。
2. 飞船高阶玩法不足：已有舰队 / 改装 / 船员，但没有战斗、乘客、外观等大系统。
3. 剧情演出不足：已有章节任务和事件文本，但没有对话树 / 剧情演出引擎。
4. 远期平台能力仍未做：背景音乐、音频资源包、动态音乐、多人、i18n、云存档都还没开始；基础短音效 MVP 已经接入。

### 建议的文档口径

- 对外可以明确表述为：“核心单机贸易经营版与中期专题教学已实现；基础短音效已接入；探索深化、完整音频平台、多人、国际化属于后续阶段。”
- 不再使用旧文档里 `Renderer.js`、`IndexedDB 已实现`、`TradeStationUI 独立可用` 这类已经过时的说法。

# 星际贸易商 - 技术架构设计（当前实现版）

> 更新日期：2026-08-21
> 判定基准：以当前仓库 `js/`、`ui/`、`tests/` 的实际接线为准，而不是早期泛化设计稿。
> 当前版本定位：浏览器单机版，Vanilla JavaScript + ES Modules，Vite 负责开发与生产构建，Three.js 负责主 3D 星图，Canvas 2D 提供降级渲染。

---

## 1. 技术基线

当前项目的运行时基线已经比较明确：

- 运行环境：浏览器静态页面，无服务端依赖
- 语言与模块：Vanilla JavaScript + ES Modules
- 渲染：Three.js 3D 星图 + Canvas 2D 降级 + DOM/CSS 业务界面
- 开发与构建：Vite
- 状态管理：`GameManager.js` 持有单一运行时 `_state`
- 数据定义：`js/data/*.js` 以模块常量形式提供
- 持久化：`localStorage` 多槽位存档
- 测试：Vitest 单元测试 / 集成测试

当前仓库 **没有** 以下基础设施：

- TypeScript 编译链
- 独立 ResourceManager / 音频资源管理与背景音乐调度（当前仅有轻量短音效 `AudioManager.js`）
- 网络同步层 / 云存档层
- i18n 运行时服务
- 账号体系与后端 API

## 3. 初始化流程

启动路径非常直接：

1. `js/main.js` 在页面 `load` 事件中调用 `GameManager.init()`，并等待场景 ready promise 后关闭启动层。
2. `StartupState` 解析新档或自动存档；`GameSessionLifecycle.begin()` 统一执行 stop → session replace → `GameSystemRuntime.restore()`。
3. `GameFeatureRuntime` 从 manifest 建立按需功能端口，系统恢复后同步已加载 Feature；市场、舰队、档案、设置等重模块不进入首屏静态依赖图。
4. `GameUiApplicationRuntime` 延迟组装 MarketWorkspace、Settings、GameUiCoordinator、GameUiLifecycle 与 Context adapters，并绑定 eager UI 壳。
5. `GameSessionLifecycle.present()` 统一同步星图/Renderer 投影、增量渲染、恢复待处理事件与 recurring task，再启动 `GameLoopRuntime`；它组合 `GameClockController`、场景帧、延迟功能暂停和领域日推进。
6. `StarmapRenderer.whenSceneReady()` 只在 Three 首帧或 2D 回退帧完成后兑现，避免加载层提前消失。

应用实例退出与 HMR 不复用会话 transition，而由 `GameApplicationLifecycle.shutdown()` 按 Session → Loop → 异步 controller → UI/Context → Feature → Renderer → Runtime Graph 的反向依赖顺序释放；bfcache `pagehide` 不提前销毁同一 JS 实例。

当前初始化链的特点是：

- 顺序仍是显式编排，但 state/session、system restore、Feature、UI 应用层与 game loop 已有独立 runtime 边界。
- 业务系统大多以模块函数形式暴露 `init()`、`advanceDay()`、`handleX()` 等接口。
- UI 层需要的 command 由生命周期/协调器注入，而不是 UI 直接修改全局状态；例如长期路线选择由 `VictoryRuntimeController` 提交，`FleetUI` 以请求对象接收 state 和单一 typed command 端口。Market 通过 `market-chrome` / `market-spot` / `market-capital` / `market-operations` 区分真实 render port；`MarketWorkspaceSession` 持有内容选择/图表/排序，`MarketWorkspaceEntrySession` 单独持有打开状态、浏览地点和一次性 focus。Fleet 动作区分 `fleet-hangar` / `fleet-shop`；Archive 五页也拥有独立区域。Map 会话只保存局部选择/披露区/航线焦点，Logs 会话保存历史/未读/筛选/聚合；Archive/Fleet Tab 统一由 `WorkspaceTabController` 投影。对象级操作使用 local-scope `WorkspaceActionSlot`，不会发布全局下一步。内部区域仅在所属工作区活动时渲染，隐藏工作区不后台重绘；五个 canonical workspace diagnostics 由协调器只读透传，会话 reset 与 Feature dispose 统一清理选择、表单、日志和详情 surface。

## 4. 状态管理与契约

### 4.1 单一状态源

运行时游戏状态由 `js/core/GameManager.js` 的 `_state` 持有。  
多数系统函数接收 `state` 作为参数并在其上做同步修改。

这种方案的优点是：

- 当前项目规模下调试路径清晰
- 存档序列化简单
- 测试可以直接构造状态对象
- 各系统之间共享上下文成本低

当前的代价是：

- `GameManager` 体积较大，承担了过多编排责任
- 某些流程需要严格遵守调用顺序
- 模块间仍然存在一定的隐式耦合

### 4.2 状态结构唯一来源

`js/data/constants.js` 是状态结构与持久化契约的唯一真理来源，主要包括：

- `SAVE_STATE_SCHEMA`
- `SAVE_META_SCHEMA`
- `RUNTIME_ONLY_FIELDS`
- `createInitialState()`
- `createPersistedState()`
- `INITIAL_STATE`

这意味着：

- 新增持久化字段时，必须更新 `SAVE_STATE_SCHEMA`
- 新增 `meta` 字段时，必须更新 `SAVE_META_SCHEMA`
- 运行时字段若不该入档，必须加入 `RUNTIME_ONLY_FIELDS`
- 任何文档描述都应以这些定义为准

### 4.3 状态变更入口

当前项目的主要状态变更入口集中在：

- `GameManager` 的 `_handleTravel`、`_handleOpenBuy`、`_handleOpenSell` 等动作函数
- 各系统模块导出的业务函数，例如 `Trade.travelTo()`、`Finance.takeLoan()`、`Quest.completeQuest()`
- `CommerceFacade` 提供的统一商业动作封装

总体原则是：

- UI 负责触发动作
- `GameManager` 负责调度
- `systems/*` 负责业务规则
- `_updateUI()` 在状态变更后统一刷新视图

## 5. 核心系统职责

### 5.1 经济与贸易

- `Economy.js`：供需、价格漂移、价格历史、经济周期、黑市、走私检查
- `TradeSystem.js`：买入、卖出、加油、旅行、跨星系移动
- `AutoTradeSystem.js`：自动贸易策略与路线评估
- `TradeStationSystem.js`：建站、升级、经理、策略、收益结算

### 5.2 金融与经营

- `FinanceSystem.js`：贷款、保险、股票、本地投资、信用评级
- `FuturesSystem.js`：期货合约、多空仓、保证金、结算
- `CommerceFacade.js`：给 `GameManager` 提供统一商业操作入口

当前商业终端已经不是单纯市场页，而是把：

- 现货交易
- 资本操作
- 贸易站经营

整合到 `MarketUI.js` 的统一“商业终端”内。`MarketUI` 只保留工作区状态、四个具名增量 render port、局部选择与 typed command 发布，行情图表、现货摘要、商品卡、资金、贸易站与商品详情投影分别由 `MarketChartPresenter`、`MarketSpotPresenter`、`MarketGoodsPresenter`、`MarketCapitalPresenter`、`MarketOperationsPresenter`、`MarketCommodityDetailPresenter` 拥有。商品焦点只重绘交易区，经营排序只重绘贸易站区；交易、融资和有成本经营通过动作影响矩阵同步现金相关区域，纯策略切换只失效经营区。`MarketCommand` 冻结 UI / controller 契约，`MarketWorkspaceController` 统一解释买卖、补给、贷款、投资、建站、批量策略和远程航点；商品 Context 通过统一局部 intent 进入 `WorkspaceDetailSurface`，切换远程地点会立即按最新上下文重渲染，Escape 精确返回原入口。`TradeStationUI.js` 目前仅保留为兼容层；商网总览页还承担全网批量投资、升级和策略切换的远程指令入口。

### 5.3 舰队、船员与派遣

- `FleetSystem.js`：多船管理、买卖船、切换激活船、改装、派遣航线
- `CrewSystem.js`：招募、分配、成长、船员市场
- `DispatchController.js`：派遣运行态与渲染联动

### 5.4 成长、任务与世界状态

- `FactionSystem.js`：派系关系、税率修正、黑市访问条件
- `ResearchSystem.js`：科技研究、队列与效果落地
- `QuestSystem.js`：章节任务、前置条件、推荐任务
- `AchievementSystem.js`：成就检测与奖励
- `ProgressionSystem.js`：玩家等级 / 公司等级成长
- `RandomEvent.js`：事件概率、冷却、阶段节奏、事件链
- `GalaxyDataLayer.js`：星球运行时状态与星系数据层
- `ExplorationSystem.js`：POI 调查、秘密航线、勘探报告、经营决策情报
- `GuidanceSystem.js`：根据状态和 UI context 输出唯一当前行动建议
- `GuidanceActionController.js`：将行动建议 actionType 分发到 `GameManager` 注入的执行回调
- `MidgameTeachingChain.js`：中期专题链定义与优先级逻辑；当前仍缺运行时启动、真实动作完成事件和持久化，不能视为完整运行时能力
- `VictorySystem.js`：多路径胜利判定与进度
- `TutorialSystem.js`：分步教程与新手引导

## 6. UI 与渲染架构

### 6.1 星图渲染主线

当前地图渲染入口是 `js/ui/StarmapRenderer.js`。它统一维护渲染器状态，并在 Three.js 主线与 Canvas 2D 降级路径之间切换。

它负责：

- 优先按需加载 `RendererThreeStarmap.js`，使用 Three.js 渲染 3D 星图
- WebGL2 不可用或 Three.js 尚未就绪时使用 `Renderer2DStarmap.js`
- 本地开发可使用 `?starmap=2d` 稳定验收完整降级路径；该开关只在 Vite `DEV` 模式生效
- 星球 / 星系视图切换
- 飞船飞行动画
- 派遣航线可视化
- 与设置中的动画 / 显示偏好联动

`Renderer3DAdvanced.js` 的 Babylon.js 实现仍保留在仓库中，但已不是 `GameManager` / `MapUI` 的运行时入口；当前文档与新功能应以 `StarmapRenderer.js` 契约为准。

### 6.2 UI 组织方式

UI 模块以功能面板拆分，常见模式是：

- `init(state, callbacks...)`
- `render(state, ...)`
- 根据 DOM id 直接更新片段

当前关键界面包括：

- `HUD.js`：资源、阶段、成长与胜利进度
- `MapUI.js`：星图 Context、Renderer、DOM 测量/样式投影与视图协调；只通过注入的窄 navigation port 请求工作区动作，不再导出市场或通用 Tab API
- `MapGalaxyHubPresenter.js`：星系总览解锁/访问/贸易线索模型、HTML 和单一跃迁 intent
- `MapViewStateController.js`：星系/星球视图切换、当前查看星系与悬停目标的唯一状态写入边界
- `MapExplorationPresenter.js`：POI 状态组合、探索流程模型、HTML 与稳定探索 intent
- `MapPlanetDetailPresenter.js`：星球摘要、局部航线焦点、路线估算、探索组合与 travel intent
- `MapPanelLayout.js`：根据容器、Renderer 坐标、面板高度和 Command Slot 净空计算冻结几何模型
- `MapPanelController.js`：统一解析星系、星球、POI、披露区与 Escape intent，并只调用注入端口
- `MarketWorkspaceEntryController.js` + `Session`：独占商业工作区打开/关闭、浏览位置、待聚焦请求、入口/星系导航 DOM 与刷新生命周期
- `WorkspaceTabController.js`：独占 Archive/Fleet Tab 的 listener、roving tabindex、ARIA、方向键、深链、关闭和 dispose
- `WorkspaceActionSlot.js`：纯生成带 local scope、workspace、context 与 action id 的局部操作槽；领域 controller 继续解释 intent
- `LogsWorkspaceSession.js`：保留 200 条原始会话记录，持有类型/时间筛选和可逆的短时重复聚合状态
- `LogsWorkspaceController.js`：协调日志筛选控件、列表 DOM、未读 Badge、Context 与稳定消息 ID
- `MarketUI.js`：现货 / 资本 / 经营三合一商业终端
- `FleetUI.js`：舰队工作区状态、Context 同步、详情弹层与 typed command 协调
- `FleetHangarPresenter.js`：机库主视图只读模型、HTML 和单一容器 UI intent 协议
- `FleetShopPresenter.js`：船坞采购评分、预算/席位信号、船卡 HTML 和单一购买 intent 协议
- `FleetCrewPresenter.js`：船员详情只读模型、分区 HTML 和单一 roster intent 协议
- `FleetModPresenter.js`：改装、结构升级、港口保养与资产处置只读模型、HTML 和单一 UI intent 协议
- `FleetDispatchPresenter.js`：自动跑商策略验证、路线估算、风险/阻塞信号、推荐匹配和 CTA 呈现模型
- `WorkspaceObjectDetailPresenter.js`：任务、科技、派系、成就、探索报告与通讯日志的共享 L4 事实投影；领域 UI 继续拥有各自 selector
- `WorkspaceContextAdapters.js`：把 archive 五类不可变 Context key 映射到独立 detail type，并统一 revision、Escape 与焦点返回
- `WorkspaceSurfaceController.js`：把唯一 active workspace 投影为五个同级 region 的 `is-active`、`inert`、`aria-hidden`、来源相关焦点与诊断快照
- `UIManager.js`：底栏工作区导航、底栏焦点保留、程序化入口在延迟 Feature 完成后的 generation-safe 焦点提交与星图背景模糊；MapUI 只通过生命周期注入的 navigation port 请求切换
- `SurfaceManager.js`：只管理 Blocking Surface、焦点陷阱与唯一 Escape dispatcher，不持有任何 L3 workspace DOM 或 primary/secondary 兼容状态
- `ActionGuideUI.js`：非阻塞当前行动条
- `CommandAction.js`：统一 CTA 的 surface / intent / verb 元信息和执行反馈
- `QuestUI.js`、`ResearchUI.js`、`FactionUI.js`、`SaveUI.js`、`TutorialUI.js`

### 6.3 事件通信

`EventBus.js` 是当前的横向解耦机制，主要用于：

- 日志消息广播
- 教程完成通知
- 某些 UI 层提示与状态同步

它不是完整状态管理库，更像一个轻量的发布 / 订阅工具。

## 7. 存档与数据持久化

### 7.1 当前存档方案

存档系统由 `js/systems/save/SaveSystem.js` 提供，当前方案为：

- 介质：`localStorage`
- 槽位：4 个（0 自动存档，1-3 手动存档）
- 结构：`SaveEnvelope = { meta, data }`
- 版本：`SAVE_SCHEMA_VERSION = 17`
- 游戏版本字段：`GAME_VERSION = 0.6.4`

### 7.2 当前已实现能力

- 存档保存 / 读取
- 槽位列表与损坏槽位识别
- JSON 导入 / 导出
- schema 迁移
- 运行时字段剔除
- 存档摘要信息生成
- 星系探索状态迁移与恢复
- 中期专题教学链状态的迁移、嵌套规范化与恢复

### 7.3 当前未实现能力

- IndexedDB 存档
- 云存档 / 多端同步
- 账号绑定档案

因此文档里如果提到 IndexedDB、账号云档或服务端同步，必须明确为**远期规划**，不是现状。

## 10. 文档口径建议

对外描述当前项目时，建议统一使用以下表述：

1. 这是一个浏览器单机星际贸易经营游戏。
2. 当前主干实现基于 `GameManager` 单一状态编排，而不是服务端驱动架构。
3. 当前商业、舰队、任务、金融、贸易站、研究、成就、胜利、存档都已接入主流程。
4. 探索 MVP、行动引导和统一命令 CTA 已接入主流程，后续重点是中期经营联动。
5. 基础短音效已接入现版本；背景音乐、音频资源包、动态音乐、国际化、云存档、多人属于后续平台能力。
6. `StarmapRenderer.js`、`MarketUI.js`、`MapUI.js`、`UIManager.js` 与 `ActionGuideUI.js` 分别是地图渲染门面、商业终端、星图交互、全局视图管理和行动引导的真实运行时入口。

这份文档的目标不是给未来所有可能形态预留想象空间，而是让开发者在打开仓库后，能立刻理解**当前代码到底怎么跑**。

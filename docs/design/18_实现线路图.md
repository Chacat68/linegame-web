# 星际贸易商 - 实现线路图（基于 2026-03 当前仓库）

> 目的：基于当前已实现功能与设计文档缺口，给出一份可执行、可迭代、可验收的实现路线图。
> 适用范围：当前仓库 `js/` 架构（Vanilla JS + ES Modules）
> 当前判断：项目已完成“核心可玩原型”，下一阶段重点不再是补齐基础交易闭环，而是先做稳态建设，再补中后期深度系统，最后再推进外围能力。

---

## 一、当前项目阶段判断

当前仓库已经稳定具备以下主链路：

- 核心贸易循环
- 动态经济与价格波动
- 随机事件与事件链
- 任务、成就、派系、研究、胜利条件
- 舰队管理、飞船升级、自动派遣
- 教程、HUD、星图、市场、存档

因此，项目当前更接近：

**可玩的单机原型 / 中期内容扩展前夜**

这意味着接下来的工作，不应继续平均分散，而应按以下原则推进：

1. 先稳住已有系统，避免后续扩展导致破档和回归。
2. 再补“直接增强可玩深度”的系统，而不是优先做外围大工程。
3. 最后再做多人、本地化、完整音频这类投入大但不影响单机核心闭环的能力。

---

## 二、实现优先级原则

### P0：稳态建设

目标：让当前版本可持续迭代。

2026-08-29 进展：Game Application/Runtime Graph 已替代大型组合根，Context Inspector、UI 刷新协调器和星图 UI 已按 Session/Presenter/Controller 拆分；其中星图面板投影、Context/Escape 与 Renderer/EventBus/DOM listener 生命周期已分别由 `MapPanelViewController`、`MapContextController`、`MapInteractionController` 独占，`MapUI` 只保留组合协调。

优先处理：

- 存档契约
- GameState 边界
- 数值配置化
- 最小回归测试
- 文档口径统一

### P1：单机深度增强

目标：补足设计中最影响中期体验的核心系统。

优先处理：

- 商品深度
- 黑市/特殊市场
- 飞船经营深度
- 技能树与长期成长
- 贸易站与帝国建设

### P2：沉浸与内容完成度

目标：提升感知质量与长期留存。

优先处理：

- 音效与音乐
- 更多任务链与事件层次
- 视觉资源完善
- 更多星球设施交互

### P3：平台能力扩展

目标：为商业化和长期运营预留能力。

优先处理：

- 本地化/i18n
- 云端存档或更大容量存储
- 数据驱动工具链

### P4：网络化与社交化

目标：从单机扩展为长期服务型项目。

优先处理：

- 排行榜
- 异步社交
- 多人同步框架

## 三、推荐实现顺序

## 阶段 A：基础稳态（1-2 周）

### 目标

把当前“能玩”版本提升到“适合持续开发”的状态。

### 必做事项

1. 冻结 GameState 与 SaveEnvelope 契约
- 明确哪些字段属于核心状态。
- 明确默认值来源。
- 规定每次改状态结构必须带迁移补丁。

2. 统一存档策略
- 短期继续使用 localStorage。
- 明确迁移到 IndexedDB 的触发条件，而不是立即切换。

3. 将关键经济参数配置化
- 供需恢复速度
- 峰值事件概率
- 税率修正
- 科技与派系加成顺序

4. 建立最小回归集
- 交易买入/卖出
- 旅行与燃料消耗
- 存档保存/读取/迁移
- 任务推进
- 事件触发与结算

5. 清理文档口径
- README
- MVP 路线图
- 设计实现对照表
- 新路线图文档

### 阶段验收

- 改一个系统不会轻易破档。
- 价格与任务逻辑有自动化基线。
- 文档能准确反映当前实现状态。

---

## 阶段 B：贸易深度升级（2-4 周）

### 目标

把当前“基础贸易循环”升级成“可研究、可规划、可取舍”的贸易系统。

### 必做事项

1. 商品属性扩展
- 为商品增加合法性。
- 为易腐商品增加保质期或时间损耗。
- 为高阶商品增加品质层级。

2. 市场层次扩展
- 在公开市场之外加入黑市。
- 先做黑市 MVP，不直接做拍卖行和期货。
- 黑市入口与派系友好度联动。

3. 市场信息增强
- 展示价格历史趋势。
- 展示近期波动原因。
- 展示风险标签和推荐去向。

4. 自动贸易从“固定路线”升级到“条件驱动”
- 允许设置价格阈值。
- 允许设置最低利润率。
- 允许设置风险回避偏好。

5. 垄断与特殊市场效果做轻量版
- 不先做完整金融市场。
- 先实现少量可感知的市场控制奖励。

### 阶段验收

- 玩家需要判断“是否合法、是否保值、是否值得囤货”。
- 黑市成为一条独立发展路线。
- 自动贸易不再只是机械循环。

---

## 阶段 C：飞船与经营深度（3-5 周）

### 目标

把“多艘船”升级成“真正的经营系统”。

### 必做事项

1. 船员系统 MVP
- 每艘船有船员容量。
- 船员至少包含角色、等级、工资、特长。
- 船员对交易、维修、燃料效率产生加成。

2. 飞船维护系统
- 引入磨损或维护度。
- 长期航行与事件会增加维护成本。
- 高级船只收益高，但维护压力更大。

3. 飞船获取方式扩展
- 除直接购买外，加入任务奖励船和特殊事件船。
- 拍卖获取可后置，不放在本阶段主线。

4. 改装系统细化
- 保留当前货舱/引擎/船体结构。
- 增加少量“功能型改装”，例如隐藏货舱、冷藏舱、预警器。

5. 舰队分工明确化
- 护航船
- 运输船
- 快速侦察/高利润短线船

### 阶段验收

- 不同船型真正形成差异化玩法。
- 船员和维护成本构成新的经营压力。
- 舰队不再只是“多几个 cargo 容器”。

---

## 阶段 D：长期成长与帝国建设（3-6 周）

### 目标

建立中后期目标，解决后期“钱很多但没处花”的问题。

### 必做事项

1. 技能树系统
- 从当前固定等级奖励升级为技能点分配。
- 优先做 3 条树：贸易、舰队、派系。
- 探索和社交技能可以后续补。

2. 贸易站系统 MVP
- 可在特定星球建设贸易站。
- 提供仓储、价格加成或被动收益。
- 与派系关系和区域安全度挂钩。

3. 公司经营层
- 让 companyLevel 不只是展示值。
- 公司等级绑定更多席位、特权、站点数量或折扣。

4. 中后期任务链
- 派系路线分化。
- 贸易站建设任务。
- 区域影响力任务。

5. 胜利条件重校准
- 让贸易、科技、外交、探索几条路线耗时更接近。

### 阶段验收

- 玩家在 10 小时后仍有长期目标。
- 财富不再只用于买船和升级。
- 贸易帝国建设真正成立。

---

## 阶段 E：沉浸与表现层（2-4 周）

### 目标

增强反馈感和世界感，让系统的价值被玩家感知到。

### 必做事项

1. 音频系统基础版
- UI 点击音效
- 交易成功/失败音效
- 航行与事件音效
- 背景音乐最少两组：主界面、游戏内

2. 视觉反馈增强
- 更明确的交易收益反馈
- 星球特色视觉标签
- 任务/事件的重要性视觉分层

3. 事件与任务的表现层增强
- 关键事件使用更强弹窗表现
- 关键剧情奖励加入专属演出

4. 美术资源逐步替换
- 星球插画
- 更完整的飞船图标/卡面
- 派系视觉识别强化

### 阶段验收

- 玩家能明显感知交易成功、升级、风险和节奏变化。
- 游戏从“功能原型”提升到“有完成度的产品”。

---

## 阶段 F：平台能力与全球化（2-5 周）

### 目标

为后续发行或更大范围测试做准备。

### 必做事项

1. i18n 基础架构
- 抽离硬编码文案。
- 建立翻译 key。
- 先支持简中/英文双语。

2. 设置系统扩展
- 语言切换
- 音量控制
- 音效/音乐开关

3. 存储层升级预案
- 当存档体积增长后，再引入 IndexedDB。
- 保留 localStorage 导入导出兼容。

4. 数据驱动内容组织
- 任务、事件、商品扩展尽量走数据表。
- 降低新增内容的代码改动成本。

### 阶段验收

- 新增一门语言不需要大面积改业务代码。
- 音频和语言都纳入设置系统。
- 内容扩展成本开始下降。

---

## 阶段 G：社交与多人预研（远期）

### 目标

在不推翻当前单机架构的前提下，为联网能力做最小可行验证。

### 建议顺序

1. 先做异步能力
- 本地排行榜
- 云端排行榜
- 成就分享

2. 再做轻社交
- 每日挑战
- 赛季分数
- 固定种子市场竞赛

3. 最后再评估实时多人
- 实时多人需要服务端权威架构。
- 当前项目不应直接跳到合作/竞争同步世界。

### 阶段验收

- 社交化先建立在异步比较而非实时同步之上。
- 确认用户需要后，再进入 WebSocket/房间制多人。

---

## 四、明确不建议现在就做的事项

以下功能设计上存在，但不建议在当前阶段抢先实现：

1. 完整实时多人
- 工程量大。
- 会重构状态与同步模型。
- 当前单机深度还未补齐。

2. 完整金融市场
- 贷款、股票、基金、衍生品设计过大。
- 会显著拉高平衡成本。
- 当前更适合先做贸易站和轻投资系统。

3. 完整战斗系统
- 会扩展出武器、敌人 AI、伤害结算、地图表现等大量子系统。
- 当前项目主轴仍是贸易经营，不应提前稀释开发资源。

4. 高复杂度拍卖行
- 适合放在黑市和特殊商品系统成熟之后。

## 六、最终建议

如果只选择一条最务实的路线，建议严格按下面顺序推进：

1. 先做稳态和测试
2. 再做黑市、商品深度、自动贸易增强
3. 再做船员、维护、贸易站
4. 再做技能树和中后期任务链
5. 最后补音频、本地化和联网能力

原因很简单：

- 这条顺序能持续提高当前版本可玩性。
- 每一阶段都能产生清晰可见的玩家收益。
- 不会过早进入高成本、低反馈的大工程。

这也是当前仓库从“原型”走向“完整产品”风险最低的一条路线。

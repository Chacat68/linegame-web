# 事件系统现行规则（按代码实现）

本文基于当前代码实现整理，不以策划草案为准。

- 事件数据源：js/data/events.js
- 事件核心逻辑：js/systems/event/RandomEvent.js
- 触发入口：js/core/GameManager.js
- UI 展示：js/ui/EventUI.js
- 系统参数：js/data/constants.js 中 EVENT_CONFIG 与 DIFFICULTY_LEVELS

## 1. 触发时机

随机事件仅在“旅行抵达后”尝试触发。

执行位置：GameManager 的旅行处理流程中，在研究推进、自动修复后触发，随后才进行自动存档与船队日结算。

特殊规则：新手教程激活期间不触发随机事件。

## 2. 触发概率

默认基础概率：0.25（25%）

最终概率公式：

最终概率 = 基础概率 × 难度事件系数 × 科技系数

其中：

- 难度事件系数（DIFFICULTY_LEVELS.*.eventChanceMod）
  - easy: 0.8
  - normal: 1.0
  - hard: 1.3
- 科技系数
  - 若已研究 deep_scanner：再乘 1.5

若随机判定未命中，当前无激活事件。

## 3. 事件池筛选规则

### 3.1 基础筛选（getEligibleEvents）

只有同时满足以下条件的事件才进入候选池：

1. 不是 chain 阶段事件（chain 事件不进入普通随机池）
2. condition(state) 为 true（若定义）
3. 不在冷却中
4. 符合阶段规则
5. 通过保护阈值规则

### 3.2 阶段规则（EVENT_CONFIG.stages）

- early：day <= 12 或 playerLevel <= 3
- mid：已脱离 early，且 day <= 35 或 playerLevel <= 6
- late：不满足 early/mid 时
- chain：仅通过事件链调度触发

### 3.3 保护阈值规则（EVENT_CONFIG.protection）

默认阈值：

- lowHullThreshold: 35
- lowFuelThreshold: 20
- lowCreditsThreshold: 150
- earlyDangerousMaxDay: 10
- earlyDangerousMaxLevel: 3

判定规则：

- dangerous 事件在“开局保护期（day<=10 且 level<=3）”被屏蔽
- 若事件声明 avoidWhenLowHull 且当前 hull<=35，则屏蔽
- 若事件声明 avoidWhenLowFuel 且当前 fuel<=20，则屏蔽
- 若事件声明 avoidWhenLowCredits 且当前 credits<=150，则屏蔽
- 若事件声明 bypassProtection，则跳过上述保护判断

## 4. 选取机制（权重随机）

从候选池按权重抽取：

- 事件基础权重：event.weight
- 难度风险修正：DIFFICULTY_LEVELS.*.eventRiskWeights[risk]
- 实际权重 = event.weight × risk 修正

风险修正：

- easy: safe 1.2, risky 1.0, dangerous 0.7
- normal: safe 1.0, risky 1.0, dangerous 1.0
- hard: safe 0.9, risky 1.05, dangerous 1.4

## 5. 冷却、历史与状态同步

### 5.1 冷却

- 全局配置 cooldownDays = 10
- 触发后写入 _eventCooldowns[eventId] = currentDay
- 同一事件在 10 天内不会再次进入候选池

### 5.2 历史

- 记录结构：{ eventId, day, choiceIndex }
- 最多保留最近 30 条
- 在选择结算时入历史

### 5.3 存档字段

事件相关持久化字段：

- _pendingChainEvents（since v2）
- _eventCooldowns（since v6）
- _eventHistory（since v6）

系统在 roll/resolve/getEligible 前会将运行时缓存与 state 同步；触发与结算后会写回 state。

## 6. 事件链规则

### 6.1 调度

若事件定义了 chainFollowUp：

- 按玩家选择索引匹配后续事件 ID
- 写入 state._pendingChainEvents
- scheduledDay = 当前 day + chainDelay（默认 3）

### 6.2 触发优先级

每次 rollEvent 会先检查是否存在“到期的待触发链事件”。

- 若存在，直接触发该链事件，不走普通随机池
- 该链事件会从 pending 队列移除

### 6.3 现有链路

- distress_signal
  - 选 0（前往救援）-> 5 天后 distress_followup_rescue
  - 选 1（扫描残骸）-> 5 天后 distress_followup_loot
- pirate_ambush
  - 选 2（全速逃跑）-> 7 天后 pirate_revenge

链事件本身 stage=chain，且部分定义了 protection.bypassProtection=true，保证剧情后续可触发。

## 7. 当前事件清单（代码实际）

普通池事件：

- early/safe: merchant_caravan, distress_signal, trade_festival
- early/risky: abandoned_station
- mid/dangerous: pirate_ambush, solar_storm
- mid/risky: fuel_crisis
- late/dangerous: wormhole_anomaly
- late/risky: alien_artifact, mysterious_signal

链事件：

- distress_followup_rescue（chain/safe）
- distress_followup_loot（chain/dangerous）
- pirate_revenge（chain/dangerous）

## 8. 事件结算与 UI 行为

- 触发后设置当前激活事件 _activeEvent，并发出 event:triggered
- UI 展示事件标题、描述、图标、风险标签、阶段标签、链路标签
- 玩家点选后执行 choice.effect(state)
- 结算后记录历史、调度后续链事件（若有）、清空 _activeEvent、发出 event:resolved

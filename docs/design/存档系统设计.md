# 星际贸易商 - 存档系统设计（Web 版本）

## 系统概述

存档系统用于将玩家游戏进度持久化到本地，核心目标是：

- 数据完整性：保存/加载可校验、可回退
- 版本兼容：支持 schemaVersion 迁移
- 可用性：多槽位 + 自动存档 + 可选导出/导入

在 Web（浏览器）技术基线下：

- 当前存储介质：localStorage（已实现，4 槽位，schemaVersion 迁移已接入）
- 可选：导出/导入 JSON 文件（用于备份、迁移浏览器/设备）

远期选项：

- 当单存档体积、写入频率或浏览器配额成为瓶颈时，再评估迁移到 IndexedDB

### 当前实现口径（2026-05-30）

- 状态与存档契约的唯一代码来源：`js/data/constants.js`
- 当前 schemaVersion：13
- 当前 gameVersion：0.6.1
- 当前 SaveEnvelope 继续采用 `meta + data` 结构
- `meta` 至少包含：`schemaVersion`、`gameVersion`、`slotId`、`saveName`、`timestampMs`、`day`、`credits`、`currentSystem`、`difficulty`、`companyName`、`isAutosave`
- `data` 直接保存归一化后的 GameState 顶层字段，读档时统一补默认值并执行版本迁移
- 明确不持久化的运行时字段：`hoveredSystem`
- 当前已落地迁移链路：v1 逐步迁移到 v13，实际迁移函数以 `js/systems/save/SaveSystem.js` 为准
- 系统级状态当前至少保留：`economyCycle`、`galaxyStates`、事件冷却 / 历史、金融、期货、剧情标记 / 剧情选择和公司指令领取记录

## 存档数据结构

### 结构约定（SaveEnvelope）

当前存档采用“信封 + 负载”的结构，便于扩展、迁移与校验：

```json
{
  "meta": {
    "schemaVersion": 13,
    "gameVersion": "0.6.1",
    "slotId": 1,
    "saveName": "我的商业帝国",
    "timestampMs": 1760000000000,
    "day": 18,
    "credits": 2048,
    "currentSystem": "sol_prime",
    "difficulty": "normal",
    "companyName": "星际信使贸易公司",
    "isAutosave": false
  },
  "data": {
    "companyName": "星际信使贸易公司",
    "credits": 2048,
    "difficulty": "normal",
    "day": 18,
    "currentSystem": "sol_prime",
    "fleet": [],
    "researchOptions": [],
    "_pendingChainEvents": [],
    "economyCycle": null,
    "galaxyStates": {},
    "storyFlags": {},
    "storyDecisions": {},
    "companyDirectiveClaims": {}
  }
}
```

说明：

- `schemaVersion`：存档结构版本（用于迁移），与 `gameVersion` 分离
- 当前 `meta` 刻意保持轻量，只保存槽位展示和迁移所需的最小摘要
- `meta` 默认值与生成逻辑由 `createSaveMeta(...)` 统一提供

### 当前冻结的 GameState 契约

当前代码将以下顶层字段视为稳定存档契约的一部分：

- 基础信息：`companyName`、`difficulty`、`day`、`currentSystem`、`currentGalaxy`、`viewingGalaxy`、`mapView`
- 经营与资产：`credits`、`cargo`、`cargoCost`、`maxCargo`、`fuel`、`maxFuel`、`fuelEfficiency`、`purchasedUpgrades`
- 飞船与船队：`shipHull`、`maxHull`、`autoRepair`、`fleet`、`activeShipIndex`、`fleetSlots`
- 成长与统计：`tradeCount`、`totalProfit`、`maxSingleProfit`、`goodsTraded`、`totalEvents`、`daysWithoutDamage`、`playerLevel`、`experience`、`companyLevel`、`companyExperience`
- 系统进度：`factionRelations`、`reputation`、`researchedTechs`、`currentResearch`、`researchQueue`、`researchOptions`、`techBuyDiscount`、`techSellBonus`
- 任务与成就：`questPhase`、`quests`、`completedQuests`、`achievements`
- 探索、事件与剧情：`visitedSystems`、`visitedGalaxies`、`galaxyStates`、`_pendingChainEvents`、`_eventCooldowns`、`_eventHistory`、`_tripsSinceLastEvent`、`economyCycle`、`storyFlags`、`storyDecisions`
- 公司经营：`companyDirectiveClaims`
- 经营扩展：`crewRoster`、`crewCounter`、`crewMarket`、`tradeStations`
- 金融扩展：`creditRating`、`loans`、`stockPortfolio`、`stockMarket`、`tradeInvestments`、`insurancePolicies`、`insuranceClaims`、`financeLastProcessedDay`、`futuresContracts`、`futuresLastProcessedDay`

约束：

- 新增字段必须同时补充默认值与迁移逻辑
- 删除或重命名字段必须递增 `schemaVersion`
- UI 临时状态与纯运行时字段不得直接写入存档
- `tests/helpers.js` 中的测试状态必须从同一套状态工厂生成，不能再手写影子状态

## 存档策略

### 存档槽位管理

槽位配置：

```
总槽位数：4
├── 1-3：手动存档槽位
└── 0：自动存档槽位（特殊）
```

当前实现：

- 当前实现使用 `localStorage` 键 `startrader_save_<slotId>`
- `slotId=0` 为自动存档，`slotId=1..3` 为手动存档
- UI 展示来自 `meta` 的摘要信息
- 自动存档与手动存档共用同一套 SaveEnvelope 结构

### 自动存档机制

当前触发点：

- 当前在每日推进流程中调用一次 `Save.saveGame(0, state, { isAutosave: true })`
- 自动存档写入槽位 `0`

当前特征：

- 自动存档发生在日结算链路内，和船队收益、经济推进等状态更新处于同一批次
- 当前实现没有额外的节流、备份槽或二阶段提交

当前写入策略：

- 由 `saveGame` 直接序列化当前归一化状态并覆盖对应槽位
- 写入失败时返回失败消息，不会额外生成备份副本

### 后续优化方向（未实现）

若存档体量较大或自动存档频繁，可引入“脏标记（dirty flags）”机制：

- 系统层维护变更点（如 `credits`、`fleet[0]`）
- 自动存档仅写入增量（delta）或仅写入被标记的子树

简化方案（推荐先做）：

- 当前先保持“全量保存 + 明确迁移链路”，待性能出现瓶颈再升级

## 数据安全与防篡改（可选）

在纯前端环境中，任何“加密密钥”都会随代码分发，因此存档安全更多是：

- 防误操作与防损坏（校验、备份、回退）
- 防低成本修改（可选：校验和/签名），但不应当作为强反作弊手段

建议：

- `checksum`：对 `meta + data` 做哈希（如 SHA-256）用于损坏检测
- `signature`：可选（HMAC），主要用于“检测是否被改动”，不保证无法伪造

## 版本兼容性

### 版本号管理

- `schemaVersion`：只反映存档结构与字段语义变化
- `gameVersion`：游戏发布版本（用于展示/排查问题）

### 迁移逻辑（当前口径）

当前 `SaveSystem` 使用逐版本迁移链，读到旧版本时从当前版本逐步推进到 `SAVE_SCHEMA_VERSION`；读到未来版本时显式拒绝加载，避免静默吞掉未知字段。迁移函数的完整列表以 `js/systems/save/SaveSystem.js` 为准。

示意：

```js
function migrateSave(envelope, toSchemaVersion) {
  let current = envelope.meta.schemaVersion ?? 1;
  let next = envelope;

  while (current < toSchemaVersion) {
    next = runMigrationStep(next, current, current + 1);
    current += 1;
    next.meta.schemaVersion = current;
  }

  if (current > toSchemaVersion) {
    throw new Error('Unsupported future schemaVersion=' + current);
  }

  next.data = normalizeState(next.data);
  next.meta = createSaveMeta(next.meta.slotId, next.data, next.meta);
  return next;
}
```

当前版本链路至少覆盖：

```text
v1 -> v2  基础事件链和经济周期补齐
v2 -> v3  走私统计 / 舰船改装兼容
v3 -> v4  船员名册
v4 -> v5  船员市场
v5 -> v6  随机事件冷却与历史
v6 -> v7  贸易站状态
v7 -> v8  金融系统
v8 -> v9  期货系统
v9 -> v10 星系数据层与事件静默期
v10 -> v11 剧情触发标记
v11 -> v12 剧情选择记录
v12 -> v13 公司指令奖励领取记录
```

## 当前存档 API

当前代码直接暴露以下函数，定义见 `js/systems/save/SaveSystem.js`：

```js
saveGame(slotId, state, options)
loadGame(slotId)
listSlots()
deleteSlot(slotId)
exportSave(slotId)
importSave(slotId, jsonStr)
```

说明：

- `saveGame` / `loadGame` 会负责 `meta + data` 信封封装、归一化和迁移
- `importSave` 先解析并迁移，再改写目标槽位 `slotId`
- `listSlots` 只返回槽位摘要，不返回完整 `data`
- 若后续更换底层存储实现，优先保持这组业务 API 不变，避免 UI 层跟随重写

## 错误处理

### 常见错误与处理（Web 语境）

```
1. 存储空间不足（QuotaExceededError）
   - 提示用户清理浏览器站点数据
  - 删除不需要的手动存档
  - 改用导出 JSON 做长期备份

2. 浏览器禁用/限制存储（无痕模式/隐私设置/第三方环境）
   - 提示用户更换模式或允许站点存储
  - 当前实现没有“仅会话内存档”降级路径

3. 数据损坏（校验失败/JSON 解析失败）
  - 当前会返回读档/导入失败消息
  - 保留原槽位数据，不额外执行自动回退

4. 版本不兼容（缺少迁移路径）
   - 显示明确提示与风险说明
   - 保留原始存档，不做破坏性写入
```

## 性能优化

当前实现优先保证正确性，性能优化按出现瓶颈再逐步引入：

- 限频（throttle）：避免高频动作下重复全量写入 localStorage
- 拆分数据：如未来引入更大体积的摘要字段，再考虑拆分存储
- 增量保存：dirty flags + 局部写入
